> **群 · 26,499 成员 · 可见 300 条 · 发言人 66 · bot 消息 0% · 100 条/天 · 存活率 40.21%**
> 数据来源：`scripts/tg_recon.py dump BotTalk --limit 300` → [data/recon/BotTalk.jsonl](../data/recon/BotTalk.jsonl)
> 抓取时间 2026-09-19（含发言人字段的重抓） · 样本 300 条（2026-09-15 → 2026-09-19，跨度 3 天）

**一句话结论：一个讨论怎么写 Telegram 机器人的群，里面一个机器人都没有。bot 消息 0 条——而本批十个群里，六个中文群全部部署了 bot。它的正文中位长度是 50 个字，本批十群里最高，第二名（[M_Team_Chat](M_Team_Chat.md)）只有 10 个字。300 条消息里有人在贴自己的仓库地址、有人在讨论某个客户端库不支持的特性、有人在问「有谁在用某家云的最小机型跑 bot，真的够用吗」。它的存活率 40.21%，而它没有做任何治理——和 [v2rayN](v2rayN.md) 一样，它靠的是话题本身的门槛。**

## 二、核心发现一：主题是 bot，群里一个 bot 都没有

**这是本语料里最直接的一个反差。**

**本批十个群的 bot 占比：**

| 群 | 语言 | bot 占比 |
|---|---|--:|
| [M_Team_Chat](M_Team_Chat.md) | 中 | 19% |

| [gouwu](gouwu.md) | 中 | 9% |

| [GIFgroupTW](GIFgroupTW.md) | 中（繁） | 3% |
| [beijingz](beijingz.md) / [giantcutie6688](giantcutie6688.md) / [nexitallyusers](nexitallyusers.md) | 中 | 1% |
| **BotTalk** | **英** | **0%** |
| [PublicTestGroup](PublicTestGroup.md) | 英 | 0% |

**一个由 bot 开发者组成的群，本该是最容易部署 bot 的地方——他们自己就会写。而它是本批 bot 占比最低的两个之一。**

**合理的解释有两条，数据都支持：**

1. **懂 bot 的人知道 bot 的代价。** 群管 bot 需要读取全群消息（本语料在 [Hao12News](Hao12News.md) 第九节分析过这构成个人信息处理活动）。**一群清楚这一点的人，不会为了防垃圾就把全群对话交给第三方 bot。**
2. **不需要。** 第三节论证：话题门槛已经完成了过滤。

**这个观察对本语料的"bot 占比"指标是一次重要修正。** 此前在 [M_Team_Chat](M_Team_Chat.md) 第三节写过"bot 占比不是活跃度指标，是'群在做什么'的指标"，**现在要再加一条：bot 占比低也可能意味着'群里的人懂 bot'，而不是'群没人管'。** 单看数字会得出完全相反的判断。

## 三、核心发现二：正文中位 50 字——本批最高，而且高得不成比例

| 群 | 正文中位 | 内容性质 |
|---|--:|---|
| **BotTalk** | **50** | **技术问答** |
| [M_Team_Chat](M_Team_Chat.md) | 10 | 站务闲聊 |
| [v2rayN](v2rayN.md) | 10 | 关键词指令 + 短问答 |
| [PublicTestGroup](PublicTestGroup.md) | 8 | 社交破冰 |
| [beijingz](beijingz.md) | 7 | 城市闲聊 |
| [gouwu](gouwu.md) | 6 | 短语/表情 |
| [jinan_tg](jinan_tg.md) | 3 | bot 关键词 |
| [GIFgroupTW](GIFgroupTW.md) | 0 | 纯贴图 |

**50 字是第二名的 5 倍、中位数的 7 倍。**

**原因是技术问答无法压缩。** 样本里能看到的发言包括：贴出一个代码仓库让对方参考、描述一个按钮回调在带某个标志位时的行为、说明某个上游库不支持某项特性并附上 issue 链接、询问某家云服务商的最小机型跑 bot 是否够用。**每一条都必须把上下文写清楚，否则没人能回答。**

**这与 [jinan_tg](jinan_tg.md) 的 3 个字构成本语料群类正文长度的两个极端**，而两端的成因恰好相反：**jinan_tg 的 3 个字是因为要说的话被 bot 的关键词表规定死了；BotTalk 的 50 个字是因为要说的话没有任何模板可用。**

**发言人 66、top10 占 49%，是本批分散度第三的群**（仅次于 [beijingz](beijingz.md) 30%、[jinan_tg](jinan_tg.md) 32%，但那两个的"分散"是垃圾账号造成的）。**在真实对话的群里，49% 是一个很健康的数字——有稳定的答疑者，也有源源不断的提问者。**

## 四、核心发现三：40.21% 的存活率，靠的是话题门槛

**与 [v2rayN](v2rayN.md)（41.10%）几乎相同，而两者都是技术群、都几乎不做治理。**

**本语料的"群存活率"成因至此四种：**

| 成因 | 机制 | 样本 | 存活率 |
|---|---|---|--:|
| **对话速度** | 消息几秒就被刷走，投广告不划算 | [PublicTestGroup](PublicTestGroup.md) | **85.71%** |
| **话题门槛** | 垃圾发布者不会来一个看不懂的群 | **BotTalk**、[v2rayN](v2rayN.md) | **40%–41%** |
| 身份绑定 | 成员有可被封禁的站外账号 | [M_Team_Chat](M_Team_Chat.md) | 26% |
| 无门槛 + 通用名 | 什么人都来，靠平台封号清理 | [beijingz](beijingz.md)、[gouwu](gouwu.md) | 0.02%–0.10% |

**"话题门槛"这一条在 BotTalk 上比在 [v2rayN](v2rayN.md) 上更纯粹**：v2rayN 好歹还有一个关键词 bot 在挡重复问题，**BotTalk 什么都没有，它靠的完全是"你得先懂才能说话"。**

**而 40.21% 仍然意味着 60% 的消息不在了。** 对一个没有治理的技术群，这部分最可能是：**成员自己删的**（贴错代码、发错链接）、**账号注销后消息消失**、以及少量被平台清理的垃圾。**这与 [beijingz](beijingz.md) 的 99.9% 不是一回事——前者是正常损耗，后者是被淹没。**

## 五、实现技术思路

**这个群没有任何"实现"：零 bot、零置顶规则（样本中未见）、零标签体系、零文件托管、零自建工具。**

**它的全部基础设施是"一个群"。**

**外链结构值得单独看**——19 条外链全部是技术资源：

| 域名 | 次数 | 性质 |
|---|--:|---|
| `t.me` | 7 | 群/频道引用 |
| 平台官方文档 | 5 | Bot API 文档 |
| 平台 API 端点 | 2 | |
| 代码托管平台 | 2 | 成员自己的仓库 |
| 平台自家发布工具 | 1 | |
| 两个第三方客户端库的文档站 | 各 1 | |

**零商业域名、零联盟参数、零收款账号、零优惠码。** 这在本语料的群类样本里只有 [PublicTestGroup](PublicTestGroup.md) 和 [GIFgroupTW](GIFgroupTW.md) 能比，**而那两个的"干净"是因为没内容可放链接；这个群外链很多，只是全都指向文档和仓库。**

**这是本语料第一个"外链密集但全部非商业"的样本。** 此前的判断规则是"看域名就能判断有没有变现"（[tginfoen](tginfoen.md) 第三节确立），**这个样本说明规则要加一条前提：域名的数量不说明问题，域名的性质才说明问题。**

## 六、成本

**经常性（月）：¥0。**

| 项目 | 金额 |
|---|--:|
| bot | ¥0（没有） |
| 管理人力 | ¥0–100（无可见管理动作，但 66 个发言人的技术群偶尔需要有人答疑） |
| 服务器 / 域名 / 托管 | ¥0 |

**与 [PublicTestGroup](PublicTestGroup.md) 并列本语料成本最低。**

**但它和 [PublicTestGroup](PublicTestGroup.md) 的"零成本"性质不同：** 那个群的价值完全由闲聊产生，**运营者不需要提供任何东西**；**这个群的价值由答疑产生，而答疑是有成本的——只不过成本由回答问题的成员承担，不由运营者承担。**

**样本中 top10 发言人占 49%，其中几个明显在持续回答别人的问题。** 这部分人的时间投入在本报告里不可量化，**但它是这个群真正的成本项，而且完全由志愿者承担。**

**这与本语料的 [QuanX_API](QuanX_API.md)（维护者一个人扛 4,105 条评论，最终公开抱怨并停更）形成对照：** **把答疑分散给社区，比集中在一个人身上可持续得多。**

## 七、收益

**¥0。**

**19 条外链全部是技术资源，零商业域名、零联盟参数、零收款账号、零广告、零置顶推广（样本可见范围内）。**

**未变现的潜在价值：** 2.65 万成员的 Telegram bot 开发者群。**这是一个高价值受众**——bot 开发者会为 VPS、托管服务、数据库、API 服务付费，**而样本中恰好出现了一条成员自发的云服务器讨论（问某家云的最小机型够不够用）。**

**这类受众在开发者广告市场的定价显著高于泛受众。** 按置顶月租计：**¥800–4,000/月**；若按赞助式合作（云厂商赞助开发者社区是成熟做法）计，**量级可到 ¥3,000–15,000/月。**

**区间宽的三条原因：**

1. **英文开发者社区的赞助通常是年度打包**，而不是按月计价，**月度折算误差大。**
2. **群没有任何商业化基础设施**（无置顶广告位、无赞助致谢、无 bot 可插推广），**从零开始商业化需要先建这些。**
3. **最关键：商业化会直接冲击第四节的"话题门槛"机制。** 一旦开始接广告，**这个群就有了"值得投放"的信号，而这个信号本身会吸引垃圾发布者。** **它现在的干净，部分来自"这里没钱可赚"这个事实。**

**这是本语料第一次把"不变现"本身识别为一种治理手段。** 此前记录过"不变现是产品特性"（[douban_read](douban_read.md) 的存档公信力）、"不变现是独立性要求"（[tginfoen](tginfoen.md)、[LptTech](LptTech.md)、[QuanX_API](QuanX_API.md)）、"不变现是母品牌结构"（[sspai](sspai.md)、[jin10light](jin10light.md)）——**"不变现所以垃圾不来"是第四种，而且它只在群这种形态上成立。**

**2.65 万成员来自"Telegram Bot"这个主题词。** 本语料的"关键词占位"至此第七种形态——**技术主题占位**，与 [GIFgroupTW](GIFgroupTW.md) 的兴趣占位、[PublicTestGroup](PublicTestGroup.md) 的平台名占位并列，**但它自带受众筛选：只有真的在写 bot 的人才会搜这个词。**

**这解释了它为什么能在零运营、零 bot、零治理的情况下维持 40.21% 的存活率和 49% 的发言分散度**——**获客渠道本身就是过滤器。**

**它的天花板也由此确定：** Telegram bot 开发者的总量有限，**这个群不可能像 [beijingz](beijingz.md)（城市名）或 [PublicTestGroup](PublicTestGroup.md)（平台名）那样无限吸纳。** 2.65 万可能已经接近这个细分人群在 Telegram 上的规模上限。

## 九、法律风险

**风险等级：低。** 本批十群里与 [PublicTestGroup](PublicTestGroup.md) 并列最低。

- **群主的管理义务。** 可见内容全部是技术讨论，**40.21% 的存活率且幸存内容完全干净**——**这是"群内本来就没有违法内容"的正面证据。** 对照 [gouwu](gouwu.md)（幸存内容里挂着黑产广告，证明没清理）。
- **管辖连接点薄弱。** 内容为英文，讨论对象是一个境外平台的开发接口，**成员分布在多个法域**，中国法没有实际的管辖连接点。
- **技术讨论本身不构成风险。** 讨论 Bot API 的用法、第三方库的特性、云服务器选型，**在任何法域下都是中性的技术交流。** 样本中**没有出现任何关于爬取用户数据、批量注册、绕过限流、群发骚扰的讨论**——**而这些恰恰是 bot 开发社区最可能出现的灰色话题。** 这一点本报告专门核查过，**300 条里没有。**
- **成员自贴仓库的著作权。** 有成员贴出自己的代码仓库供他人参考，**这是自有作品的主动分享，不涉及侵权。**
- **零 bot = 零数据处理。** 与 [PublicTestGroup](PublicTestGroup.md) 相同：运营者在技术上不持有任何成员数据。**这一点在一个 bot 开发者群里尤其值得指出——他们完全有能力部署监控 bot，但没有。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名、0 个客服账号）；不涉及传播淫秽物品罪（0 条成人内容）；不涉及侵犯著作权罪（无内容分发，外链全部指向公开文档与成员自有仓库）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流）；不涉及非法经营罪（零收入、零商业痕迹）；不涉及侵犯公民个人信息罪（无 bot、无数据收集）；不涉及《计算机信息网络国际联网管理暂行规定》（与 [v2rayN](v2rayN.md)、[projectXtls](projectXtls.md) 不同，本群的技术主题与网络管控规避完全无关）。

**责任主体**：群主与管理员，**身份在样本中不可见**。**暴露面与 [PublicTestGroup](PublicTestGroup.md)、[GIFgroupTW](GIFgroupTW.md) 并列本批最小**——零域名、零商业外链、零收款、零 bot。
