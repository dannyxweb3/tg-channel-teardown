## 二、核心发现一：转发量的第五种边界

**转发均值 0.7、中位 0——300 条里超过一半一次都没被转发过。**

**这在本语料是一个极端值。** 对照本批：

| 样本 | 转发均值 |
|---|--:|
| [tgx_perfection](tgx_perfection.md) | 77.2 |
| [AndroidThemesGroup](AndroidThemesGroup.md) | 58.4 |
| [zrj96](zrj96.md) | 9.1 |
| [lover_links](lover_links.md) | 8.6 |
| [lychee_wood](lychee_wood.md) | 4.9 |
| [zhihuribao_rss](zhihuribao_rss.md) | 3.8 |
| **cool_scripts** | **0.7** |

**而它的 ERR 是 10.37%，与 [kejiqu](kejiqu.md)（9.99%）、[lychee_wood](lychee_wood.md)（10.30%）同档**——**看的人不少，转的人几乎没有。**

**本语料此前记录过转发驱动的四种边界：**

| 边界 | 样本 | 机制 |
|---|---|---|
| 时间边界 | [zuanke8](zuanke8.md) | 线报过期了，转出去没用 |
| 形式边界 / 可转述性 | [TimeHorizonX](TimeHorizonX.md) | 内容离开上下文就散了 |
| 合法性边界 | [magazinesclubnew](magazinesclubnew.md) | 转出去会给自己惹麻烦 |
| 竞争性边界 | [Licensesss](Licensesss.md) | 席位有限，转了自己就没了 |

**这个样本是第五种：适用性边界。**

> **内容只对已经在用这个工具的人有意义。** **转给别人不是"不想转"，是"转了对方看不懂、也用不上"。**

**判据很干净：** 正文是版本号 + 变更条目（「后端 2.24.17 / 前端 2.17.35 / 新版某客户端 3.5.0(969) 及以上版本的资源解析器插件」），**这段文字对一个没装过这个工具的人是完全不可解析的。**

**这条边界与前四种的区别在于：前四种都是"内容本身可以转，但有理由不转"；这一种是"内容本身不具备可转性"。**

**本语料由此可以把转发量的解释框架收紧：**

> **高转发 = 内容可独立理解 + 有分享动机。** **两个条件缺一不可，而它们失效的方式各不相同。**

**反过来看，这也说明 ERR 10.37% 全部来自订阅者自己**——**没有外溢，1,687 次阅读就是 1.63 万订阅里真正在用这个工具的那部分人。**

**这是本语料第一次能用转发量反推"订阅者中的真实用户比例"：约 10%。**

## 三、核心发现二：一个重复了 257 次的错别字

**257 条帖子的页脚是同一组四个标签：**

```
#SubStore #更新记录 #changlog #updates
```

**`changlog` 少了一个 `e`。正确拼法是 `changelog`。**

**这个错拼在 257 条帖子里一次都没有被修正。**

**本语料在 [v2rayN](v2rayN.md) 第二节记录过同类现象：那个群的关键词 bot 里有一个从未被修正的错别字（「文挡」应为「文档」）。**

**两个样本合起来给出一条可用的判据：**

> **一个在大量样本中完全一致的错别字，是模板存在的直接证据。** **人工输入会偶尔打对；模板不会。**

**它比时间指纹更强的地方在于：** 本语料的 cron 指纹分析（[sspai](sspai.md) 分钟 `:20` 100%、[hacker_news_feed](hacker_news_feed.md) 分钟模 10 = 0、[programmerjokes](programmerjokes.md) `:30` 98%）**需要足够的样本量才能看出规律，而一个固化的错别字只要出现两三次就足以判定。**

**本语料在 [ruanlu](ruanlu.md) 第四节修正过一条判据（格式固定只能说明"有模板"，不能说明"有脚本"）。这条错别字判据回答的正是"有没有模板"那一半**——**它与"有没有脚本"是两个独立的问题。**

**四个标签的构成本身也值得记一笔：**

| 标签 | 语言 | 功能 |
|---|---|---|
| `#SubStore` | 产品名 | **主题** |
| `#更新记录` | 中文 | 类型 |
| `#changlog` | 英文（错拼） | 类型 |
| `#updates` | 英文 | 类型 |

**后三个是同一个意思的三种写法。**

**本语料的"标签九用"**（[zrj96](zrj96.md) 第四节确立第九种"事件直播串"）**在这里出现第十种：同义多语堆叠。**

**它的用途是跨语言检索**——**一个中文用户搜 `#更新记录`、一个英文用户搜 `#updates`，都能落到同一批帖子上。**

**代价是那个错拼：搜 `#changelog`（正确拼法）的人一条都搜不到。** **一个为检索而设的标签，因为一个字母的失误，对它的目标用户完全失效，而且失效了 257 次。**

## 四、核心发现三：每一条都挂着作者频道

**300 条帖子，300 条带同一个 `t.me` 链接，指向作者的主频道。覆盖率 100%。**

**本批已经出现过一次这个结构：** [zhihuribao_rss](zhihuribao_rss.md) 的 298/300 条页脚挂着「频道大全」。

**两者的性质不同：**

| | [zhihuribao_rss](zhihuribao_rss.md) | **cool_scripts** |
|---|---|---|
| 挂的是什么 | **矩阵目录**（"频道大全"） | **作者本人的频道** |
| 频道与枢纽的关系 | **同一运营者的几十个节点之一** | **一个项目的专用日志频道** |
| 目的 | **交叉导流** | **把用户引回作者** |

**第二种在本语料是第一次见到，它对应一种具体的运营结构：**

> **作者把"我在做什么"与"这个项目更新了什么"拆成两个频道。**

**这么做的理由可以从数据里读出来：** **这个频道 1.09 帖/天、转发 0.7、评论 12 条——它是一个噪声很低的通知流。** **如果把版本日志混进作者的主频道，主频道的信噪比会被 300 条版本号淹没。**

**本语料的"矩阵识别五法"至此可以补上第六法：**

> **100% 覆盖率的单向页脚链接。** **当一个频道的每一条内容都指向同一个外部账号且没有例外时，这两个账号属于同一运营者。**

**它与已有五法的区别是精确性：页脚链接密度（第一法）是一个统计特征，100% 覆盖率是一个确定性判据。**

**本样本同时提供了一个对照：` t.me` 总共 316 次，其中 300 次指向作者频道，另外 16 次分散在 5 个第三方账号上（某讨论群 6 次、某客户端频道 3 次、其余各 1 次）。** **自有节点与第三方引用的比例是 300:16。**

**本语料在 [tgzhcn](tgzhcn.md) 第四节做过同类测算（自有节点 40/44、第三方 2/4），这是第二个可比数据点，而且比例更悬殊。**

## 五、核心发现四：一个新的文件名形态

**8 个文件全部是 mp4，其中一个的文件名是：**

`iShot_2026-04-24_16.42.07.mp4`

**这是 macOS 上一款截图/录屏工具的默认命名格式：`iShot_YYYY-MM-DD_HH.MM.SS`。**

**本语料的"文件名取证九形"至此第十形：桌面截屏工具的默认命名。**

**它与已有九形的定位关系：**

| 形态 | 说明什么 |
|---|---|
| hash + 时间戳 | 有脚本 |
| `IMG_####` / `.MOV` | iOS 相机直出 |
| `RPReplay_Final####` | iOS 录屏 |
| 标题 + 话题串 | 短视频下载器 |
| 语义命名 | 有剪辑导出 |
| `YYMMDD_主体_节目_v1` | 有制作流程 |
| 同名 APK ×192 | 手工 Gradle 发布 |
| 下载.mp4 | 下载器默认 |
| `<name>.mkv_<sec>.png` | ffmpeg 抽帧 |
| **`iShot_<日期>_<时间>`** | **macOS 桌面录屏工具直出** |

**第十形的信息量在于它定位了工作环境：macOS 桌面端，而不是手机。**

**这与这个频道的内容一致**（一个开发工具的演示录屏），**也与 8 个文件全是 mp4、平均每个不到 550 KB 一致**——**短的功能演示片段，不是完整教程。**

## 六、实现技术思路

| 层 | 做法 |
|---|---|
| 内容 | **版本号 + 变更条目**（正文中位 183 字） |
| 引用 | **代码托管 369 次**（1.23 次/帖）——指向提交与发布页 |
| 标签 | **四标签模板**，257 条一致 |
| 页脚 | **作者频道链接，300/300** |
| 演示 | 8 段 macOS 录屏 |
| 互动 | 评论开放但冷清（12 帖 / 48 条） |

**自动化程度需要分开看：标签模板与页脚是固定的（说明有模板），但正文的变更条目是逐条手写的**（每条描述的技术细节不同，且出现「感谢群友 @… 的建议」这类人工致谢）。

**这正是 [ruanlu](ruanlu.md) 第四节那条修正的又一个例证：有模板不等于有脚本。** **这个频道是"人工填模板"。**

**代码托管 369 次 / 300 帖 = 1.23**——**本语料代码托管引用密度最高的样本**（对照 [zrj96](zrj96.md) 9 次 / 300 帖、[daily5kong](daily5kong.md) 44 次 / 300 帖）。

**存活率 99.7%（300 条只删了 1 条）**：**版本日志是纯追加的时间序列，与 [jin10light](jin10light.md)、[zhihuribao_rss](zhihuribao_rss.md) 同型。** **删掉一条历史版本记录没有任何意义——它正是这类内容的价值所在。**

**经常性（月）：¥0–100。**

| 项目 | 金额 | 依据 |
|---|--:|---|
| 频道 | ¥0 | 零 bot、零自有域名、零服务器 |
| **发布日志的时间** | — | **1.09 帖/天，每条要整理变更条目** |
| 项目本身的成本 | **不属于本频道** | 开源项目的服务器与开发时间 |

**这个频道的成本结构是本语料最特殊的一个：它本身几乎零成本，但它是一个有真实开发成本的项目的附属品。**

**本语料的开源工具样本**（[projectXtls](projectXtls.md)、[QuanX_API](QuanX_API.md)、[ACL4SSR](ACL4SSR.md)、[surfboardnews](surfboardnews.md)）**都面临同一个结构：代码是免费的，而写代码的时间不是。**

**[ClashR_for_Windows_Channel](ClashR_for_Windows_Channel.md) 第三节的结论"变现能力与代码贡献度成反比"在这里再得一例**——**一个持续 276 天、300 个版本的项目，其发布频道零广告、零赞助入口、零收款。**

## 八、收益

**可观测：¥0。**

**300 条里零收款账号、零联盟参数、零推广码、零赞助链接、零订阅墙。**

**11 条广告粗筛命中全部是技术语境的误报**：样本中「某些机场你还是用不了」「有些机场后端会下发负数」是在描述协议兼容性与响应头解析的技术问题。

**本语料的"关键词假阳性十八类"在这里得到一个新的子类：**

> **工具文档里的服务名。** **一个代理订阅管理工具的更新日志必然反复提到"机场"，因为那是它要解析的数据源。** **这与已记录的"同形异义"（机场 = airport）不同——这里的"机场"就是那个意思，但语境是技术兼容性而非推广。**

**本语料"不变现的十种类型"**（[zhihuribao_rss](zhihuribao_rss.md) 第八节确立第十种）**在这里属于已有的"不该变现"一类**（与 [QuanX_API](QuanX_API.md)、[tginfoen](tginfoen.md) 同组）：**一个工具的官方更新日志挂广告会直接损害工具的可信度。**

**未变现的承载力：¥500–4,000/月。**

**四条依据：**

1. **受众极度垂直且有购买力**：1,687 次阅读全部是这个工具的实际使用者，**而这个工具的用户必然同时是代理服务的付费用户。** **本语料在 [speedcentre](speedcentre.md)（271 个推广链接）、[ClashR_for_Windows_Channel](ClashR_for_Windows_Channel.md)（176 个）见过这条链路的定价成熟度。**
2. **但触达规模小**：1,687 人/帖，**是本批个人频道里偏低的。**
3. **转发 0.7 意味着零外溢**——**广告主付的钱只买到订阅者，买不到扩散。**
4. **上锚受一个结构性因素压制：这个位置一旦卖了，工具的中立性就没了。** **本语料在 [QuanX_API](QuanX_API.md) 第七节论证过同一点。**

**区间宽的原因：本语料的代理生态定价样本都是"推广位"（按链接分成），而这个频道若变现只可能是"赞助"（按月固定），两种模式没有可换算的锚。**

## 十、法律风险

**风险等级：低。**

- **工具本身不构成风险。** 这是一个订阅配置的转换与管理工具，**不提供节点、不提供订阅内容。** 与本语料 [QuanX_API](QuanX_API.md)、[surfboardnews](surfboardnews.md)、[v2rayN](v2rayN.md)、[loveapps](loveapps.md) 的分析一致：**此类工具不符合《刑法》第 285 条第 3 款"专门用于侵入、非法控制计算机信息系统"的要件**——**它处理的是配置文件格式，本身与"侵入"无关。**
- **但它比那几个更靠近链路核心，这一点需要说清楚。** 这个工具的功能是解析、合并、分发代理订阅。**本语料在 [ClashR_for_Windows_Channel](ClashR_for_Windows_Channel.md) 第三节做过代理生态六层切分；这个工具属于"配置工具"层。** **该层在本语料中被观察到的共同特征是：变现能力最低而技术贡献最高**（[QuanX_API](QuanX_API.md) 0 个推广链接 / ERR 81.5%），**而低变现在法律上恰恰是有利的——它切断了非法经营罪与帮信罪共同需要的营利要件。**
- **本频道零推广。** 300 条里零收款、零联盟参数、零机场推广码。**这是它与 [v2rayN](v2rayN.md)（bot 播报招商邮箱，本语料给出高风险判断）的关键区别，也是它与 [ClashR_for_Windows_Channel](ClashR_for_Windows_Channel.md)（176 个推广链接）的关键区别。**
