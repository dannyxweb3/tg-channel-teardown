## 二、核心发现一：本批最安静，也最健康

**2.68 条/天是本批十一个群的最低值**，而**存活率 54.2% 是第三高**。

**把本批所有群按"可见/天"与"存活率"排开：**

| 群 | 可见/天 | 存活率 |

| [VodStore](VodStore.md) / [hao123f](hao123f.md) / [PublicTestGroup](PublicTestGroup.md) / [V2EXPro](V2EXPro.md) | 300 | 77.7% / 44.1% / 85.7% / 76.1% |
| [loveapps](loveapps.md) | 150 | 27.9% |
| [wikipedia_zh_n](wikipedia_zh_n.md) / [ruanlu](ruanlu.md) | 100 | 94.9% / 35.3% |
| [ngcss](ngcss.md) | 12.5 | 15.6% |
| [GIFgroupTW](GIFgroupTW.md) | 5.0 | 2.26% |

| [beijingz](beijingz.md) / [gouwu](gouwu.md) | 1.2 / 0.1 | 0.10% / 0.02% |

**在"可见/天"最低的四个群里，另外三个的存活率都在 2.26% 以下，只有这个是 54.2%。**

**这说明它的低活跃是真实的低活跃**——**不是"消息被删光了造成的假象"。** [beijingz](beijingz.md) 的 1.2 条/天背后是 1,210 条/天的垃圾吞吐；**这个群的 2.68 条/天背后只有 4.95 条/天的 id 增长。**

**本语料由此得到一条判断：`可见/天` 单独看会误导，必须配 `id/天` 与存活率一起读。** 三个数字组合起来才能分辨"安静"与"被淹没"。

**这个群是"真安静"：没人刷屏，也没人来发垃圾。**

## 三、核心发现二：12 条域名

**112 天、300 条消息，外链总数 12 条**——**代码托管平台 5、`t.me` 2、其余六个域名各 1。**

**这在本语料的技术群里是最少的：**

| 群 | 外链数 | 每条消息 |
|---|--:|--:|
| [BotTalk](BotTalk.md) | 19 | 0.06 |
| **pythonzh** | **12** | **0.04** |
| [ruanlu](ruanlu.md) | 约 34 | 0.11 |
| [loveapps](loveapps.md) | 3 | 0.01 |

**与 [loveapps](loveapps.md)（3 条，全是平台自身域名）相比，这个群至少还在贴代码托管链接与文档。**

**成因与 [loveapps](loveapps.md) 第二节相同：正文中位 15 字的短问答，答案是一句话而不是一个链接。** **本语料"零/极少外链"的第五种成因（对话不需要链接）在这里再得一例。**

**样本中可见的发言形态是具体的技术问题与答复**（某个库的写法、某个模块的行为、申请某个组织账号），**这是一个真实在用的问答群。**

**标签只有两个，各 1 次：`#history`、`#ot`。** **`#ot` 是 off-topic 的缩写**——**一个中文群使用英文缩写标记跑题内容，与 [misakatech](misakatech.md) 的中文自嘲标签（`#不是科技圈的日常`）是同一种用途的两种写法。** 本语料"自嘲式偏题标记"至此两个样本。

**这是本批分散度最高的真实社区**（[beijingz](beijingz.md) 的 162 人 / 30% 更分散，但那是垃圾账号造成的）。

**top10 占 50% 意味着另外 61 个人贡献了另一半消息**——**没有任何一个人主导这个群。**

**bot 只有 1 条**——**这个群没有部署任何治理工具，而它依然干净（2 条粗筛命中均为误报）。**

**成因是 [BotTalk](BotTalk.md) 第四节确立的"话题门槛"：** 来发广告的人不会来一个讨论 Python 的群。**而这个群的门槛比 [BotTalk](BotTalk.md) 更高一层——它不只需要懂技术，还需要懂中文技术社区的语境。**

## 五、实现技术思路

**零实现：1 条 bot 消息、零标签体系、零文件托管、零置顶规则（可见范围内）、零域名。**

**全部基础设施就是"一个群"，与 [BotTalk](BotTalk.md) 相同。**

**`t.me` 引用 2 条：一次自指、一次指向一个疑似同名的备用群**——**这是本语料常见的"备用号"配置，但只有 1 次引用，说明不是主动导流。**

## 六、成本

**经常性（月）：¥0。**

**与 [BotTalk](BotTalk.md)、[PublicTestGroup](PublicTestGroup.md)、[wikipedia_zh_n](wikipedia_zh_n.md)、[loveapps](loveapps.md) 同属零成本档。**

**答疑成本由回答问题的成员承担**（71 个发言人、top10 只占 50%，说明答疑是分散的）——**与 [BotTalk](BotTalk.md) 第六节的结论一致：把答疑分散给社区，比集中在一个人身上可持续得多。**

**这个群的分散度比 [BotTalk](BotTalk.md)（66 人 / 49%）还略高，说明它的答疑负担分摊得更均匀。**

## 七、收益

**¥0，且没有任何变现痕迹。**

**未变现的承载力：** 2.26 万成员的中文 Python 开发者群。**受众质量高**（与 [BotTalk](BotTalk.md) 第七节分析的是相邻人群），**但 2.68 条/天的活跃度意味着任何广告的曝光都极其有限。**

**按置顶月租计：¥300–1,500/月。**

**区间比 [BotTalk](BotTalk.md)（¥800–15,000）低得多，原因只有一个：活跃度。** **一个每天只有 2.68 条消息的群，成员打开它的频率很低，置顶位的实际曝光远低于成员数所暗示的。**

**本语料由此补一条：群类广告位的定价锚是"日活跃消息数"而不是"成员数"。** [PublicTestGroup](PublicTestGroup.md) 第七节论证过"群是流式版面，只有当下这一屏有效"——**而一个几乎不动的版面，连"当下这一屏"都没有人看。**

**这层筛选的代价是天花板：中文 Python 开发者的规模小于全球 Python 开发者。** **2.26 万可能已接近上限。**

## 九、法律风险

**风险等级：低。** 与 [BotTalk](BotTalk.md)、[PublicTestGroup](PublicTestGroup.md)、[wikipedia_zh_n](wikipedia_zh_n.md) 同属本语料最低的一档。

- **内容：纯技术问答。** 样本中未见任何涉及爬虫滥用、批量注册、绕过风控的讨论——**而这些是 Python 社区最可能出现的灰色话题**，本报告专门核查过，**300 条里没有。**
- **群主的管理义务：履行情况良好。** 存活率 54.2% 且幸存内容完全干净、零 bot 零治理工具——**这是"群内本来就没有违法内容"的证据，而非"清理有效"。**
- **境内连接点。** 简体中文、成员以中文开发者为主，**中国法有管辖意义**——**但内容本身不涉及任何违法事项。**
- **零数据处理。** 无 bot，运营者在技术上不持有任何成员数据。
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（0 条成人内容）；不涉及侵犯著作权罪（无内容分发，12 条外链指向公开仓库与文档）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（无数据收集）。

**责任主体**：群主与管理员，**身份在样本中不可见**。**暴露面：零域名、零商业外链、零收款、零 bot——与 [BotTalk](BotTalk.md)、[PublicTestGroup](PublicTestGroup.md)、[GIFgroupTW](GIFgroupTW.md) 并列本语料最小。**
