## 二、核心发现一：产业链最上游的那一环

2026-07-05 的公告（阅读 35,762、转发 623，两项全样本第一）原文要点：

> **「由于中国翻墙娱乐圈…带不动，且几乎无国人捐款反而一直喂国字头 [某商业客户端]，以及为了规避风险，Project X 即日起完全转向俄罗斯和伊朗，严格禁止在中国大陆内使用，不再处理中国 GFW 相关事件，比如不会为了对抗中国 GFW 的最新封锁而迭代，且放弃兼容中国代理软件、机场等生态」**

前一天（07-04）的一条帖把经济逻辑说得更直接：

> **「我也脱离 GFW 的集火专注对抗 RKN 了，收俄罗斯的赞助又与中国无关」**

`RKN` 即俄罗斯联邦通信监督局。**这句话把整件事讲完了：同一套协议技术，对抗谁取决于谁付钱。**

**本语料的 2026 年产业链时间线至此补全为三段：**

| 时间 | 环节 | 来源 | 关键证据 |
|---|---|---|---|
| **2026-04** | **机房 / IDC** | [vps_xhq](vps_xhq.md) | 「4 月 1 日开始的专项整治」997 转发；「关闭对等流量的服务」806 转发；月度转发峰值 388 |
| **2026-04** | **机场 / 分销** | [jichangtj](jichangtj.md) | 「4 月起…持续被拔线中」1,118 转发；「向前追溯三个月的倒查机制」；月度转发峰值 793 |
| **2026-07** | **协议 / 上游开发** | **projectXtls** | **「即日起完全转向俄罗斯和伊朗，严格禁止在中国大陆内使用」623 转发** |

**三个环节、三个互不相关的频道、三个月内依次发生。** 前两环是"被打"，第三环是"主动退出"——**而退出的理由不是被打，是没人付钱。**

**这条公告对本语料此前所有机场类报告的含义需要写清楚：**

本语料已分析的机场/代理生态号（[jichangtj](jichangtj.md) 13.4 万、[merlinclashcat](merlinclashcat.md) 4.76 万、[vps_xhq](vps_xhq.md) 4.96 万、[lihaiba](lihaiba.md) 3.9 万等）**全都建立在这套免费开源协议之上**，而它们的变现方式是联盟返佣、机场分销、VPS 推广——**钱在整个链条里流动，但没有流回上游。** 公告里的「几乎无国人捐款反而一直喂国字头[商业客户端]」就是在说这件事：用户愿意为一个商业客户端付费，不愿意给底层协议捐款。

**这是本语料第一次拿到"开源基础设施与其商业下游之间的分配失衡"的直接证据，而且是当事人自己说的。**

**但 2026-09 又掉回 7,439，而帖数只有 7 条。** 这说明降频带来的提升是一次性的重新分配，不是持续增长——**注意力总量没变，只是分母变了；一旦读者的打开习惯跟着调整，单帖阅读会回落。** 这是对前三个样本的一个重要补充：**"少发多读"有半衰期。**

**8 月的 12 条内容也变了。** 6–7 月是密集的技术争论与社区转发，8 月剩下的是零散的个人感想和对 GitHub 讨论的引用；9 月的最后三条全部是同一个 issue（客户端兼容性问题）的评论中继。**从"每天几十条"退化成"偶尔转一条 GitHub 通知"。**

## 四、核心发现三：65% 是转发，这个频道是一个人的思维流

**196/300 条有 `fwd_from`。** 来源构成：

| 来源 | 条数 | 类型 |
|---|--:|---|
| **GitHub** | **15** | **仓库活动中继**（commit / issue comment / discussion comment） |
| 十余个个人账号 | 各 6–10 | **社区成员的发言** |

**转自个人账号的那部分是关键。** 一个官方项目频道把社区成员在别处说的话转进来，而且占了大头——**这不是"发布"，是"引用"。** 配合正文中位 33 字（多数是一句评论），形态是：**转一段别人的话 + 一句自己的评价。**

**GitHub 中继只有 15 条，但它们的标签暴露了 webhook 的存在**：`#discussioncomment` 8、`#issuecomment` 5、`#commitcomment` 2，外加一串 issue 编号作为标签（`#6376`、`#6477`、`#6210`、`#6508`、`#6521`…）。**这是 GitHub webhook → Telegram 的标准产物**，标签由事件类型和 issue 号自动生成。

**这解释了 `间隔中位 166 秒、<60 秒占 48%`**——不是 cron，是**事件突发**：一次讨论里连着几条评论，webhook 就连着推几条。**本语料"间隔极小"的成因至此有四种：**

| 成因 | 样本 | 区分特征 |
|---|---|---|
| 高频 cron | [AI_News_CN](AI_News_CN.md) | 分钟/秒有固定值 |
| 批量补录 | [XPlus_Channel](XPlus_Channel.md) | 集中在极少数时刻 |
| 相册 | [sizukon](sizukon.md) / [douban_read](douban_read.md) | 同秒成组，组大小可数 |
| **webhook 突发** | **projectXtls** | **秒完全随机，且集中在少数 issue 号上** |

**没有 cron 指纹**（分钟 top1 占 7%、秒 top1 占 4%）——**因为事件什么时候发生，帖子就什么时候出现。**

**转发中位只有 7 而峰值 623，落差 89 倍**，也是同一个形态的结果：绝大多数帖子是内部对话，没有转发价值；少数几条是全行业要看的公告。

## 五、核心发现四：一个代理协议项目，触发了 12 次"代理"

广告粗筛命中 21 条，命中词：**代理 12**、广告 5、赞助 5、推广 1。

| 命中词 | 实际语境 |
|---|---|
| **代理** | 「Chrome 倒是支持直接设置 https:// **代理**」「本来 1:1 的**代理**流量模型 GFW 只能说是猜」——**全部是 proxy 的技术义** |
| 广告 | 「第一眼还以为是**广告**」（对某浏览器内置 VPN 的调侃）、「被诈骗**广告**骗麻了」 |
| 赞助 | 「收俄罗斯的**赞助**又与中国无关」——**这条不是广告，是收入模式的自述** |
| 推广 | 一段模仿鲁迅小说笔法的技术圈调侃 |

**"代理"在这个样本上的误报率是 100%，而且是本语料可能存在的最纯粹的一次**——**它就是一个代理协议项目**。本语料此前记过 [kejiqu](kejiqu.md) 的「住宅代理 Residential proxy」、[jike_collection](jike_collection.md) 的「代理律师」，**加上本例，"代理"一词在技术、法律、商业三种语境下各有一个完全不同的意思，而灰产语境下的"代理"（下线分销）只是第四种。**

**与此同时，"赞助"这一条是本语料第一次出现"命中词恰好指向真实收入模式，但不是广告"的情形。** 粗筛的设计意图是找"这个号在卖什么"，而这里命中的是"这个号靠什么活着"——**同一个词，一个是支出侧一个是收入侧。**

**误报谱系至此 15 类，三个成因不变（同形异义 / 报道即命中 / 分词错位），但本例给"同形异义"加了一条推论：越是垂直专业的频道，通用关键词的误报率越高。** 一个代理协议频道触发所有"代理"，一个广告业媒体触发所有"广告"，一个博彩报道号触发所有博彩黑话——**粗筛在专业频道上的信噪比最差。**

## 七、成本

**这是本语料成本结构最特殊的一个样本：频道成本几乎为零，但它背后是一个持续多年的开源项目。**

**频道侧经常性（月）**

| 项目 | 金额 | 依据 |
|---|--:|---|
| 服务器 / 域名 / bot | **¥0** | 只有一个 GitHub webhook，跑在 GitHub 自己的设施上 |
| 文件托管 | **¥0** | 3.3 MB |
| 人力 | **¥0** | 见下 |

**频道侧合计 ≈ ¥0/月。**

**"人力为零"不是修辞。** 这个频道的内容是开发者本来就在做的事的副产品：GitHub 上的技术辩论会自动中继过来，社区里看到的东西顺手转一下，想到什么写一句。**它没有选题、没有排期、没有审校、没有配图。** 对照本语料同量级的中文号——[LptTech](LptTech.md) 每条要 30–60 分钟，[douban_read](douban_read.md) 每条 15–45 分钟，**这个号每条的边际成本以秒计。**

**项目侧成本（不属于频道，但决定频道的存亡）**

| 项目 | 金额 | 依据 |
|---|--:|---|
| 核心开发 | **不可观测** | 协议设计与实现，全职级别的投入 |
| 基础设施 | ¥0–500/月 | GitHub 免费，测试服务器少量 |

**协议开发的人力投入无法从这份样本里估算**，但可以给一个下界：样本中出现的技术议题包括后量子密钥交换套件的集成、TLS 指纹一致性、客户端最小版本强制、明文协议出站禁用——**这些是需要持续跟踪 TLS 生态演进的工作，不是业余时间能维持的。**

**而第二节的公告说明了这笔成本此前由谁承担：没有人。** 「几乎无国人捐款」意味着中文用户侧的收入接近零，**开发是靠开发者自己贴，或者靠别处的收入贴。** 公告之后转向俄罗斯赞助，等于把成本转移给了新的付费方。

## 八、收益

**频道侧收入：¥0。** 86 天、300 条、0 条广告、0 个联盟参数、0 个优惠码、0 个收款入口、0 个 bot 深链。第五节已逐条排除全部 21 条粗筛命中。

**项目侧收入：捐赠 / 赞助，且模式在样本期内发生了根本转变。**

| 阶段 | 来源 | 证据 | 判断 |
|---|---|---|---|
| **2026-07-05 之前** | 中文用户捐款 | **「几乎无国人捐款」**（当事人自述） | **接近零** |
| **2026-07-05 之后** | 俄罗斯方面赞助 | 「收俄罗斯的赞助又与中国无关」 | **不可观测，但确实存在** |

**金额完全不可观测**——没有公开的捐赠地址统计、没有赞助方名称、没有金额披露。**能确定的只有方向：从"几乎没有"变成"有"，且付款方换了国别。**

**尝试给一个边界，并说明为什么区间必然很宽：**

- **下界 ¥0/月**：如果"赞助"指的是基础设施捐赠（服务器、带宽、测试环境）而非现金，现金收入仍为零。样本里没有任何一句话确认是现金。
- **上界**：一个被数千万用户使用的抗审查协议，如果由国家级或准国家级的对抗审查项目资助，量级可以到每月数万美元。**但这纯属类比推断，本样本没有任何金额线索。**

**区间给成 ¥0–数万美元/月，跨度四个数量级，这在本语料里是最大的一次。** 必须说清楚为什么不收窄：

1. **唯一的信息源是当事人在情绪化语境下的两句话**（公告本身用词激烈），**不是财务披露。**
2. **"赞助"一词在开源语境下可以指现金、服务器、法律支持、甚至只是一次性的项目补助**，四种的量级差几百倍。
3. **本语料没有任何可比样本。** 其他所有号的收入都能从广告位、联盟参数、付费入口推算；**这个号一个都没有。**

**倾向性判断：现金收入不高，但已经足以改变项目方向。** 依据是公告本身的逻辑——**如果俄方赞助金额巨大，公告不必写得这么像赌气；恰恰是"总算有人付钱了"的量级，才会让人把这件事当成一个转折点宣布出来。**

**趋势：频道侧的活跃度已经塌了**（8 月 12 条、9 月 7 条），**但这不等于项目停了**——9 月的三条 GitHub 中继说明仓库仍在活动。**频道正在退化回它最初的形态：一个 webhook 的出口。**

## 十、法律风险

**风险等级：中。** 技术本身合法，风险来自它在中国法下的用途定性，以及公告带来的一个意想不到的效果。

- **提供"专门用于"规避网络管控的工具（主要争点）。** 中国法下最相关的是《刑法》第 285 条第 3 款（提供侵入、非法控制计算机信息系统的程序、工具）与《计算机信息网络国际联网管理暂行规定》第 6 条（国际联网必须使用国家批准的信道）。**第 285 条的构成要件是"专门用于"侵入或非法控制计算机信息系统**——代理协议实现的是流量转发与加密，不侵入也不控制任何第三方系统，**在构成要件上不符合**。实务中对翻墙工具的追究更多走《治安管理处罚法》与行政处罚（《计算机信息网络国际联网安全保护管理办法》第 6 条），或者在有经营行为时走非法经营罪。**本项目零收费、零经营、纯开源，非法经营罪的经营要件不成立。**
- **2026-07-05 公告的法律效果值得单独分析。** 公告明确写明「严格禁止在中国大陆内使用」「不再处理中国 GFW 相关事件」「放弃兼容中国代理软件、机场等生态」。**这是一份公开的、可取证的用途限制声明。** 它在两个方向上起作用：
  - **对项目方有利**：它切断了"明知用于中国境内规避管控仍提供帮助"这一主观要件的认定路径。此后任何在中国境内的使用，都是违反项目明示禁止的行为。
  - **对下游不利**：本语料已分析的机场类号（[jichangtj](jichangtj.md)、[merlinclashcat](merlinclashcat.md) 等）继续基于该协议向中国用户提供服务，**现在是在明示禁止之下进行的**。这不改变它们各自的违法性认定，但在民事层面（协议许可条款）与舆论层面都多了一层不利因素。
- **言论内容。** 公告与相关帖文包含对特定商业产品和特定开发者的激烈负面评价（用词粗俗、点名批评）。**这可能构成商业诋毁（《反不正当竞争法》第 11 条）或名誉侵权（《民法典》第 1024 条）**，责任主体为发布者。减轻情节是：多数评价指向技术实现缺陷并附有技术论证（非捏造事实），且发布者与被批评方在中国境内均无明确经营主体，管辖与执行都困难。
- **中继 GitHub 内容：不构成风险。** 15 条中继的是项目自己仓库的公开活动，著作权归项目与贡献者，转述自有仓库内容不涉及侵权。
