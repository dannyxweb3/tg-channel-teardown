## 二、核心发现一：内容 100% 是附件

**300 条消息，300 条带文件。png 224 个、jpg 76 个，合计 266.5 MB。**

**本语料此前的媒体主导样本：**

| 样本 | 主导媒体 | 占比 |
|---|---|--:|
| **askahh** | **文件（截图）** | **100%** |
| [AndroidThemesGroup](AndroidThemesGroup.md) | 图片 | 81.7% |
| [tgx_perfection](tgx_perfection.md) | 图片 | 73% |
| [lychee_wood](lychee_wood.md) | 图片 | 60.3% |
| [iingtw](iingtw.md) | 图片（配图） | 90.7% |

**前四个的图片是"内容的一部分"，这个样本的截图就是内容本身。**

**正文只有 163/300 条（54%），中位 76 字——近一半的帖子连说明都没有，只有一张图加几个标签。**

**这个形态有一个直接的后果：这个频道的内容不可被文本检索，也不可被引用。**

**一张测速截图里的数字（延迟、丢包、速率）无法被复制、无法被聚合、无法被比较**——**读者只能一张一张看。**

**本语料由此得到一条：**

> **以截图为载体的内容，其可信度高于文本**（截图更难伪造，读者认为它是"实拍"），
> **而可用性远低于文本**（不可搜、不可比、不可引用）。

**这个权衡是刻意的。** **第五节会说明：可信度正是这个频道的商业基础。**

**文件名的形态是 `<服务商名>-<若干分隔符>-<四位数字>-test.png`**——**带一个固定的 `test` 后缀与一个递增编号。**

**本语料的"文件名取证十形"**（[cool_scripts](cool_scripts.md) 第五节确立第十形）**在这里得到第十一形：测试工具的批量输出命名。**

**它说明截图不是手动截的，是某个测速工具批量生成并按 `<被测对象>-<编号>-test` 命名的。**

**这对第五节有直接意义：测速流程是自动化的，而自动化的测速流程意味着可以批量接单。**

## 三、核心发现二：把三个维度压进一个标签

**标签分两类：**

| 类 | 标签 | 次数 |
|---|---|--:|
| **协议** | `#ss` | **129** |
| | `#Trojan` | 19 |
| | 其他协议 | 若干 |
| **测速环境** | `#北京联通1000m` | **38** |
| | `#甘肃电信1000m` | 34 |
| | `#辽宁联通1000m` | 24 |
| | `#广西移动1000m` | 21 |
| | `#东莞电信1000m` | 18 |
| | `#长沙电信1000m` | 17 |
| | …（更多同构标签） | |

**第二类标签的结构是 `<省份/城市> + <运营商> + <带宽>`——三个维度压进一个字符串。**

**本语料的"标签十二用"**（[projectXray](projectXray.md) 第三节确立第十二种）**里，"属性检索"这一种此前的最佳实例是 [AndroidThemesGroup](AndroidThemesGroup.md) 的颜色标签（一个维度：色系）。**

**这个样本是同一用途的高阶版本：**

| 样本 | 维度数 | 示例 |
|---|--:|---|
| [AndroidThemesGroup](AndroidThemesGroup.md) | **1** | `#dark` |
| [SteamNy](SteamNy.md) | **3（三个独立标签）** | `#喜加一` + `#Epic` + `#移动端` |
| **askahh** | **3（压在一个标签里）** | `#<省><运营商><带宽>` |

**[SteamNy](SteamNy.md) 用三个正交标签表达三个维度，这个频道用一个复合标签表达三个维度。**

**两种做法的差别是可组合性：**

> **正交标签可以任意组合筛选**（搜 `#Epic` 得到所有 Epic 的，搜 `#移动端` 得到所有移动端的）。
> **复合标签只能整体匹配**（搜 `#北京联通1000m` 只能得到这一个精确组合，搜不到"所有北京的"）。

**这个频道选择了复合，代价是失去了部分检索能力。**

**但它的选择是对的，原因在于需求形态：**

> **一个找机场的人，关心的恰恰是"我这条线"**——**北京联通和北京电信的实际表现可以差很多。** **模糊到"北京"没有意义。**

**本语料由此给"属性检索标签"补一条设计判据：**

> **当各维度的组合本身才是有意义的查询单位时，用复合标签；当各维度可以独立成立时，用正交标签。**

**`#ss` 129 次（占 43%）说明被测的机场里 SSR/SS 协议仍占多数**——**这是一个可以从标签分布直接读出的行业结构数据，本语料此前只能从 [projectXtls](projectXtls.md)、[ACL4SSR](ACL4SSR.md) 这类项目侧样本间接推断。**

## 四、核心发现三：价格被拆到了另一个频道

**`t.me` 引用 328 次，其中 167 次（51%）指向同一个配套频道，而那个频道的名字直接包含"price"。**

**这是一个明确的功能分频道结构：**

| 频道 | 内容 |
|---|---|
| **本频道** | **测速截图 + 环境标签** |
| **配套频道** | **价格/套餐** |

**本语料此前记录过两种"一个运营者两个频道"的结构：**

| 结构 | 样本 | 拆分依据 |
|---|---|---|
| 主频道 + 更新日志 | [cool_scripts](cool_scripts.md) | **信噪比**（版本号会淹没主频道） |
| 频道 + 群 + 投稿 bot | [SteamNy](SteamNy.md) | **功能**（发布 / 讨论 / 收线索） |
| **测速 + 价格** | **askahh** | **内容寿命** |

**第三种的拆分依据值得单独记：**

> **测速结果是一次性的快照**（这个时刻、这条线、这个节点的表现）。
> **价格是持续有效的状态**（套餐改了才变）。

**把两者放在一起，价格会被测速刷走；分开之后，价格频道可以保持一个可查阅的当前状态。**

**本语料由此在"频道拆分"这个运营决策上得到第三条依据：信噪比、功能、内容寿命。**

**167 次引用意味着平均每两条测速帖就指一次价格频道**——**这是一条高强度的单向导流。**

**按 [cool_scripts](cool_scripts.md) 第四节确立的"矩阵识别第六法"（100% 覆盖率的单向页脚链接），这里的覆盖率是 56%（167/300），**不构成确定性判据，但结合"两个频道的名字共享同一个前缀"这一点，同属一个运营者几乎没有疑问。**

## 五、核心发现四：一条被粗筛完全漏掉的商业链路

**本语料的广告粗筛在这个频道命中 1/300。**

**而这个频道的每一条内容都是商业内容。**

**漏报的原因是结构性的：**

| 特征 | 为什么粗筛抓不到 |
|---|---|
| **内容在图里** | 截图的文字不被抽取 |
| **正文只有标签** | 46% 的帖子没有正文 |
| **服务商名进了标签** | 标签是中性字符串，不含推广词 |
| **链接被短链包裹** | 25 次第三方短链，域名层面看不出性质 |

**本语料的漏报谱系至此三层**（[ibetame](ibetame.md) 第二节、[pdcn2](pdcn2.md) 第二节确立前两层）：

| 层 | 手法 | 样本 |
|---|---|---|
| 1 | **无文本载体**（裸链接、名片、图片） | [ibetame](ibetame.md)、[pdcn2](pdcn2.md)、**askahh** |
| 2 | 字符级混淆（插点、零宽字符） | [pdcn2](pdcn2.md) |
| 3 | 语义级伪装（黑话、日常短句） | [pdcn2](pdcn2.md)、[hao123f](hao123f.md) |

**这个样本是第一层最彻底的形态：不是"把链接藏起来"，是"内容本来就不在文本里"。**

**它给本语料的方法论一条硬性修正：**

> **对以文件为主要载体的频道，基于正文与域名的自动筛查会系统性地失效。**
> **可靠的判据是媒体构成本身：当一个频道 100% 的消息都带附件时，必须人工判读。**

**实际的商业结构从其他字段可以还原：**

| 证据 | 含义 |
|---|---|
| 七个以上机场域名，各 5–9 次 | **被推广的服务商**，非单一客户 |
| 多个机场自有频道各 8–9 次引用 | **同时给服务商的频道导流** |
| **短链服务 25 次** | **最可能是带归属标识的推广链接** |
| 自动化的测速工具命名 | **可批量接单** |
| 配套价格频道 167 次 | **把读者送去决策** |

**本语料在 [speedcentre](speedcentre.md)（271 个推广链接）第三节把"测试/广告位"列为代理生态六层切分中变现最重的一层。**

**这个样本是那一层的第二个观测点，而它的形态更成熟：**

| | [speedcentre](speedcentre.md) | **askahh** |
|---|---|---|
| 推广链接 | 271 | **短链 25 + 七个域名 + 多个频道引用** |
| 内容载体 | 图文混合 | **纯截图** |
| 广告披露 | **转发自「付费广告」频道** | **无任何标注** |
| 检索体系 | 一般 | **三维复合标签** |
| 价格 | 同频道 | **独立频道** |

**[speedcentre](speedcentre.md) 的披露是本语料"广告披露八档"的第五档；这个频道是最低档。**

**而它的产品化程度（标签体系、频道拆分、自动化测速）明显更高。**

**本语料由此得到一条不舒服但直接的观察：**

> **在这个赛道里，运营的专业度与披露的透明度不相关，甚至可能反向。**

**这与本语料在 [creativemotion](creativemotion.md) 第五节的发现一致：披露质量更可能取决于法律强制，而不是运营者的专业水平或道德。**

## 六、核心发现五：转发均值 1.2

**转发均值 1.2、中位 1、max 12——本语料非灰产样本中最低的一档**（仅高于 [cool_scripts](cool_scripts.md) 的 0.7）。

**而它的 ERR 是 17.90%，不算低。**

**看的人不少，转的人几乎没有。**

**本语料的"转发七种边界"至此**（[stopCA](stopCA.md) 第四节确立第七种）：

| 边界 | 样本 |
|---|---|
| 时间边界 | [zuanke8](zuanke8.md) |
| 形式边界 | [TimeHorizonX](TimeHorizonX.md) |
| 合法性边界 | [magazinesclubnew](magazinesclubnew.md) |
| 竞争性边界 | [Licensesss](Licensesss.md) |
| 适用性边界 | [cool_scripts](cool_scripts.md) |
| 密度边界 | [wublock](wublock.md) |
| 效用边界 | [stopCA](stopCA.md) |

**这个样本同时命中三条：**

1. **时间边界**：一张三个月前的测速截图没有参考价值。
2. **合法性边界**：转发机场推广给别人，转发者自己要承担观感与风险。
3. **竞争性边界**：本语料在 [Licensesss](Licensesss.md) 第三节论证过"有限资源不值得分享"——**一个便宜且没被用烂的机场，用户没有动力推荐给更多人。**

**三条边界叠加，解释了 1.2 这个数字。**

**这对商业模式是一个实质约束：**

> **零外溢意味着这个频道的读者规模完全由它自己的拉新决定，广告主买到的是一个封闭池子。**

## 七、实现技术思路

| 层 | 做法 |
|---|---|
| 测速 | **自动化工具，批量输出带编号的截图** |
| 发布 | 截图 + 环境标签 + 协议标签，**正文常缺省** |
| 检索 | **三维复合标签** |
| 价格 | **拆到独立频道**（167 次引用） |
| 链接 | **第三方短链**（25 次） |
| 导流 | **机场自有频道直接引用**（多个各 8–9 次） |

**链接处理落在本语料"六档"的第 5.5 档（第三方短链服务），与 [iingtw](iingtw.md) 同位置，但动机相反：**

> **[iingtw](iingtw.md)：要点击数据，不想维护域名。**
> **askahh：短链最可能承载推广归属标识，同时隐藏目标域名。**

**本语料由此把 5.5 档拆成两支：**

| 支 | 动机 | 样本 |
|---|---|---|
| 统计型 | 只为知道多少人点了 | [iingtw](iingtw.md) |
| **遮蔽型** | **隐藏目标 + 承载归属** | **askahh** |

**判据是有无商业关系：有分成的用短链是为了记账与遮蔽，没有分成的用短链只是图方便。**

## 八、成本

**经常性（月）：¥100–800。**

| 项目 | 金额 | 依据 |
|---|--:|---|
| **测速节点** | **¥100–600** | **标签显示至少六个省份 × 三家运营商的千兆线路**——**这需要在多地有真实的落地环境或代理测速合作** |
| 测速工具 | ¥0–100 | 自动化脚本 |
| 频道 / 存储 | ¥0 | Telegram 承载 266.5 MB |
| 短链服务 | ¥0–100 | 第三方 |
| 人力 | — | **0.67 帖/天，截图由工具产出，人工只需选取与打标签** |

**这是本语料成本结构最特殊的机场类样本：它的成本不在服务器上，在测速环境上。**

**`#<省份><运营商>1000m` 系列标签至少覆盖六个不同的省份与三家运营商。**

**一个人不可能同时在六个省有千兆宽带**——**这意味着要么有分布式的测速合作者，要么租用了多地的测试环境。**

**本语料由此得到一条：这类"测评号"的准入门槛不是流量，是测试环境。** **这解释了为什么本语料的代理生态样本里，测评层（[speedcentre](speedcentre.md)、askahh）只有两个，而分发层有很多个。**

## 九、收益

**估算：¥3,000–20,000/月。**

| 通道 | 估算 | 判断依据 |
|---|--:|---|
| **机场推广分成/位费** | ¥2,500–18,000 | **七个以上服务商域名各 5–9 次 + 多个服务商频道引用 + 25 次短链**——**这是一个多客户的持续投放盘** |
| 配套价格频道 | **计入上项** | 同一运营者 |
| 第三方广告 | ¥0–2,000 | 样本内未见明确的非机场广告 |

**区间宽的四条具体原因：**

1. **计费方式完全不可观测。** 短链后面是固定位费还是按注册分成，本报告无从判断。**本语料在 [sharecentre](sharecentre.md) 第八节遇到过同一问题。**
2. **客户数可见但投放量不可见。** 七个以上域名说明至少七个客户，**但每个客户的合约规模差异可能很大。**
3. **ERR 17.90% + 转发 1.2 = 封闭池子。** **触达稳定但无增长，这压低了溢价能力。**
4. **2026 年整条链路在收缩。** **本语料记录过五条独立的中断/涨价证据**（[vps_xhq](vps_xhq.md) 2026-04、[jichangtj](jichangtj.md) 2026-04、[projectXtls](projectXtls.md) 2026-07、[speedcentre](speedcentre.md) 2026-08、[ibetame](ibetame.md) 2026-09）。**本样本的数据截至 2026-05-08，其后的经营状况本报告无法评估。**

**下锚 ¥3,000：** **1.51 万订阅、单帖 2,706 阅读、七个以上并发客户的垂直测评号，按最低的固定位费估算已在四位数。**

**上锚 ¥20,000：** **对标 [speedcentre](speedcentre.md)（271 个推广链接）的规模；本样本的客户数与产品化程度接近，但触达规模更小。**

## 十、增长策略

| 机制 | 证据 | 判读 |
|---|---|---|
| **多关键词占位** | 频道名含三个协议名 + "机场测速" | **主要机制** |
| **三维标签检索** | 省份 + 运营商 + 带宽 | **留存与复查** |
| 截图可信度 | 300/300 实拍 | **信任** |
| 配套价格频道 | 167 次引用 | **闭环** |
| 转发外溢 | **1.2** | **几乎没有** |
| 互推 | 多个机场频道引用 | **输出而非输入** |
| 买粉 | **无从判断** | ERR 17.90% 不异常 |

## 十一、法律风险

**风险等级：高。**

- **机场推广（主要风险）。** 这是一个以推广代理服务为业的账号：七个以上服务商域名、多个服务商频道引用、25 次可能承载归属标识的短链。**机场服务本体落在《计算机信息网络国际联网管理暂行规定》第 6 条与《计算机信息网络国际联网安全保护管理办法》第 6 条上；为其提供有偿广告推广，可能构成《刑法》第 287 条之二帮助信息网络犯罪活动罪的"广告推广"帮助。** **参照本语料 [speedcentre](speedcentre.md) 第九节、[ClashR_for_Windows_Channel](ClashR_for_Windows_Channel.md) 第九节、[sharecentre](sharecentre.md) 第十节的同类分析。**
- **本样本的情节重于本语料的多数同类。** 三点理由：**（a）它不是顺带推广，整个频道的内容就是推广；（b）它同时服务七个以上客户，具有明显的持续经营特征；（c）它建立了完整的产品化体系（自动化测速、三维检索、价格分频道），说明这是一门经营而非偶发行为。** **"经营"这一要件的证据强度，在本语料的代理生态样本中仅次于 [speedcentre](speedcentre.md)。**
- **零广告披露。** 300 条中未见任何 `#ad`、"推广"、"合作"一类标注，**而内容全部是商业推广。** **依《广告法》第 14 条，广告应当具有可识别性；第 28 条规制虚假广告。** **本语料"广告披露八档"中，这个样本落在最低档。** **测速截图以"客观实测"的形式呈现付费推广，这一点比单纯的不标注更进一步。**
- **测速数据的真实性。** 截图由自动化工具批量生成，**外部无法验证。** **若测速结果受商业关系影响而被选择性呈现（例如只发付费客户的好成绩），则可能构成《广告法》第 28 条的虚假或引人误解的宣传。** **本报告无法判断是否存在此情形，但需指出：一个既收推广费又做"客观测评"的账号，在结构上存在这一利益冲突。**
- **境内连接点明确。** 简体中文、标签直接标注中国大陆的省份与运营商、服务对象为大陆用户、内容为绕过境内网络管控的服务测评。**这是本语料境内连接点最明确的样本之一**——**标签里写着具体省份和运营商。**
- **非法经营罪的讨论空间。** **若有偿推广被认定为经营行为且情节严重，《刑法》第 225 条有适用讨论空间**；**但本报告看不到收入规模，无法评估情节。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名、0 个客服号）；不涉及传播淫秽物品罪（300 个文件全部是测速界面截图，0 条成人内容）；不涉及侵犯著作权罪（截图为自制，无第三方内容分发）；不涉及侵犯公民个人信息罪（无 bot、无表单、无数据收集）。

**责任主体**：运营者（同时经营本频道与配套价格频道）。**暴露面：零自有域名是这个频道的刻意设计**（用第三方短链、把内容放在图里、不写推广词）；**但 25 条短链在服务端是完整可追溯的，而七个以上服务商的结算记录各自构成一条独立的证据链。** **本语料在 [sharecentre](sharecentre.md) 第十节观察过同一结构：身份不公开，但资金链路在广告主的后台里是完整的。**
