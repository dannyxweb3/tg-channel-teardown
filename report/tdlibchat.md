## 二、核心发现一：零站外依赖

**域名只有五个，全部落在两类：平台自身的官方资源（文档站、接口站、`t.me`）与开发基础设施（代码托管、包管理）。**

**没有任何一条指向独立站点、博客、教程站或商业服务。**

**本语料的"零外链"成因至此八种**（[openwrt_flippy](openwrt_flippy.md) 第三节确立第八种）：

| 成因 | 样本 |
|---|---|
| 设计如此 | [jin10light](jin10light.md) |
| 载体不含文字 | [GIFgroupTW](GIFgroupTW.md) |
| 被删光了 | [jinan_tg](jinan_tg.md) |
| 内容就是文件 | [ruheyushadiaoxiangchu](ruheyushadiaoxiangchu.md) |
| 对话不需要链接 | [loveapps](loveapps.md)、[pythonzh](pythonzh.md) |
| 内容是观点 | [V2EXPro](V2EXPro.md) |
| 商品是平台原生对象 | [AndroidThemesGroup](AndroidThemesGroup.md)、[tgx_perfection](tgx_perfection.md) |
| 平台文件托管足够 | [openwrt_flippy](openwrt_flippy.md) |

**这个样本是第九种：**

> **讨论对象就是平台本身。**
> **一个关于"如何调用平台接口"的群，它需要引用的全部权威资料都在平台的官方文档上。**

**第九种与第七种（商品是平台原生对象）的区别是：那个是分发平台定义的数据格式，这个是使用平台定义的编程接口。**

**两者的共同点是对平台的完全依赖，而这个样本的依赖是技术层面的、且是正当的**——**官方文档本来就应该是权威来源。**

**代码托管 4 次与包管理平台 1 次说明讨论涉及多语言的绑定库**（该平台的官方库有多个语言的社区封装）。

**本语料在 [BotTalk](BotTalk.md) 第五节记录过同一品类的另一个群（bot 开发），当时的域名构成也极少。**

**两个样本合起来给出一条：**

> **平台生态的开发者社群是本语料外链最少的品类，因为它们的知识边界与平台的边界重合。**

## 三、核心发现二：零 bot 的第二个实例

**在一个讨论"如何用官方库写 Telegram 程序"的群里，bot 消息数是 0。**

**本语料在 [BotTalk](BotTalk.md) 第五节提出过：**

> **bot 占比低也可能意味着群里的人懂 bot。**

**这个样本是第二个实例，而且位置更上游：**

| 样本 | 群的主题 | bot 占比 |
|---|---|--:|
| [BotTalk](BotTalk.md) | **用 bot API 写 bot** | **0%** |
| **tdlibchat** | **用官方客户端库写程序** | **0%** |
| [projectXray](projectXray.md) | 开源项目讨论 | 4%（仓库中继 + 单规则执行） |
| [Notionso](Notionso.md) | 软件用户社区 | **41%**（文档中继） |

**排在最上面的两个技术水平最高，而它们一个 bot 都没有。**

**本语料由此把那条观察说得更确切：**

> **bot 占比与社群技术水平呈反向关系，而成因有两条：**
> **（a）懂的人自己就能解决 bot 要解决的问题；**
> **（b）在一个人人都会写 bot 的群里，部署一个 bot 来回答问题是冗余的。**

**存活率 26.8%（清理率 73.2%）而没有任何可见的执行者——零 bot 消息、零管理发言。**

**按本语料在 [Notionso](Notionso.md) 第三节确立的三种可能（群管 bot / 人工管理员 / 平台自动封禁），这个样本只能落在后两种。**

**幸存内容完全干净**（粗筛 0/300，全部是英文技术问答），**所以它落在"清理有效"那一格，只是执行者不可见。**

**53.2 条/天的真实吞吐对一个 1.1 万人的技术群而言并不高**——**清掉的 73.2% 更可能是垃圾账号的自动投放被平台侧拦截，而不是人工在删技术讨论。**

## 四、核心发现三：`#icanhelp`

**三个标签各出现 1 次，其中一个直译是"我可以帮忙"。**

**这不是一个分类标签，也不是检索入口——它是一个人在表态。**

**本语料的"标签十四用"**（[pixelexperiencechat](pixelexperiencechat.md) 第三节确立第十四种"命令快捷键"）**在这里出现第十五种：自荐标签。**

**把标签按"为谁服务"重排：**

| 用途 | 为谁服务 |
|---|---|
| 分类 / 属性检索 / 栏目 / 同义多语 / 工单编号 | 读者检索 |
| 品牌 / 修辞 / 卖点 | 读者感知 |
| 纠错 / 自评 / 运营通报 | 读者知情 |
| 自嘲式偏题 / 装饰 | 社交或无 |
| 命令快捷键 | **机器** |
| **自荐** | **发言者自己** |

**第十五种是唯一一个"标签的受益者是打标签的人"的用途。**

**它与"自嘲式偏题标记"（[misakatech](misakatech.md)、[pythonzh](pythonzh.md) 的 `#ot`）最接近，但方向相反：那个是为自己的内容加免责，这个是为自己争取被找到。**

**在一个每天 14 条可见消息、64 个发言人的技术群里，一个人用标签宣告"我能帮忙"，是一个成本极低的自我推荐。**

**另外两个标签中有一个是纯数字编号**——**与 [nicegramchat](nicegramchat.md) 的 `#232`、[SteamNy](SteamNy.md) 的编号标签同属"内部编号"一类**（[projectXray](projectXray.md) 第三节确立的二分中"含义仅内部人知"那一支）。

## 六、法律风险

**风险等级：低。** 本语料风险最低的一档。

- **内容：英文的开发技术问答。** 300 条中粗筛命中 0 条，域名五个全部指向平台官方资源与开发基础设施。**未见任何推广、收款、导流或违法内容。**
- **讨论对象是平台自己的官方开源库。** **该库以开源许可发布，允许自由使用与分发；讨论其用法不产生任何许可问题。**
- **群主的管理义务：结果达标，过程不可见。** 清理率 73.2%、幸存内容完全干净、0 条粗筛命中——**但零 bot、零管理发言，执行者不可见。** **按本语料在 [Notionso](Notionso.md) 第三节的三分，这里只能推断为人工管理或平台自动封禁。**
- **零数据处理。** 无 bot、无表单、无收款——**运营者在技术上不持有任何成员数据。** **这是它与本批 [plusmsgrchat](plusmsgrchat.md)、[pixelexperiencechat](pixelexperiencechat.md)、[projectv2ray](projectv2ray.md) 的一个实质差别：那三个群部署了第三方群管 bot，各自带着一个不可评估的数据处理环节，这个群没有。**
- **境内连接点：无。** 内容为英语、讨论对象为国际平台的开发库、未见中文内容与中国大陆指向。**中国法无直接管辖意义。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（0 条成人内容，9 个文件为录屏与文本）；不涉及侵犯著作权罪（无内容分发）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（零 bot、零数据收集）；不涉及提供翻墙服务（五个域名全部是平台官方资源与开发基础设施）。

**责任主体**：群主与管理员，**身份在样本中不可见**（无管理发言、无自有 bot、无置顶可见）。**暴露面：零域名、零收款、零商业关系、零站外链接——与 [BotTalk](BotTalk.md)、[pythonzh](pythonzh.md)、[PublicTestGroup](PublicTestGroup.md) 并列本语料最小。**
