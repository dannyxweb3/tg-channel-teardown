## 二、核心发现一：站外域名为零

**300 条消息、608 个链接，全部指向 `t.me`。**

**本语料此前的最低值是本批的 [AndroidThemesGroup](AndroidThemesGroup.md)：530 个 `t.me` 对 4 个站外域名，比例 132:1。**

**这个样本是 608:0。**

**两个样本是同一个生态的两个客户端分支**（一个是官方 Android 客户端的主题，一个是 Telegram X 的主题），**而结论一致并更极端：**

| | [AndroidThemesGroup](AndroidThemesGroup.md) | **tgx_perfection** |
|---|--:|--:|
| 成员 | 20,092 | **16,486** |
| 可见/天 | 60 | **12.50** |
| 存活率 | 63.2% | **32.2%** |
| `t.me` 链接 | 530 | **608** |
| **站外域名** | **4** | **0** |
| 链接/条 | 1.78 | **2.03** |
| 正文中位 | 140 字 | **214 字** |
| 转发均值 | 58.4 | **77.2** |

**[AndroidThemesGroup](AndroidThemesGroup.md) 第二节把"商品是平台原生对象"列为本语料"零外链"的第七种成因。这个样本把它推到了极限：连那 4 个站外域名（两个应用商店链接、两个图床）都不需要。**

**本语料反复出现的结构性规律——"要做流量生意就得有域名"（[hacker_news_feed](hacker_news_feed.md)）——至此有了一个完整的反例族：** 两个样本、三万六千人、1,138 个链接、零个自有域名。

**这个反例族的适用条件很窄，可以精确表述：**

> **当商品本身是平台定义的一种数据格式时，整条链路可以不出平台。**

**代价在上一篇已经说明（百分之百的平台依赖），这里补一条更具体的：这两个群连备份都没有。** **合计 56 个文件、8.3 MB**——**一个主题生态的全部存量资产不到 10 MB，且散落在消息流里，没有任何目录、索引或外部镜像。**

## 三、核心发现二：两套分发机制并存

**这是上一篇看不到的东西：`addtheme` 深链 239 条，同时有 20 个 `.tgx-theme` 文件作为附件。**

**`.tgx-theme` 是 Telegram X 的主题文件格式。**

**[AndroidThemesGroup](AndroidThemesGroup.md) 的 300 条里只有 1 个文件（一个 5.2 MB 的 mp4），主题全部走 `addtheme` 深链；这个群的文件里有 20 个是主题本体。**

**原因是两个客户端的主题系统不同：** **`t.me/addtheme/<hash>` 是官方客户端的原生协议，Telegram X 作为一个独立分支，它的主题格式不被那套协议完全覆盖。**

**于是这个群同时跑着两条分发路径：**

| 路径 | 条数 | 摩擦 |
|---|--:|---|
| `addtheme` 深链 | **239** | **点一下** |
| `.tgx-theme` 文件 | **20** | **下载 → 在客户端里打开** |

**本语料在 [AndroidThemesGroup](AndroidThemesGroup.md) 第九节排过一条"分发摩擦谱"**（[shareAliyun](shareAliyun.md) 跳网盘→转存→下载 / [magazinesclubnew](magazinesclubnew.md) 下载 PDF→换设备 / [zaproshare](zaproshare.md) 复制订阅→粘贴 / [AndroidThemesGroup](AndroidThemesGroup.md) 点一下）。

**这个样本第一次让同一个社群里的两档摩擦同时可见，而比例是 239:20——即 92% 的分发走了低摩擦路径。**

**本语料由此得到一条可验证的判断：** **当低摩擦与高摩擦两条路径同时可用时，供给会压倒性地涌向低摩擦那一条，即使高摩擦那条能做到的事更多**（文件可以携带原生协议表达不了的主题细节）。

**文件的总量佐证了这一点：20 个 `.tgx-theme` 合计不到 4.5 MB，平均每个 200 KB 上下**——**它们不是因为体积大才用文件，是因为没有别的办法。**

## 四、核心发现三：亮色与暗色几乎持平

**标签里 `#dark` 87 + `#darktheme` 47 = 134；`#light` 78 + `#lighttheme` 56 = 134。**

**恰好持平。**

**而 [AndroidThemesGroup](AndroidThemesGroup.md) 的同一组数据是 `#dark` 98 + `#darktheme` 32 = 130 对 `#light` 32——**约 4:1。**

**同一个生态、同一类商品、同一种标签体系，暗亮比却从 4:1 变成 1:1。**

**本报告能给出两个候选解释，但无法在它们之间定论：**

1. **客户端差异。** Telegram X 的主题引擎与官方客户端不同，**亮色主题在某一边更容易做好看。**
2. **社群构成差异。** 两个群的 `转自` 来源频道完全不重叠（本群的五个来源与上一篇的五个来源没有一个相同）——**这是两个互不相通的创作者圈子，审美偏好本来就可能不同。**

**第二条解释有一条旁证：这个群的正文中位 214 字，比 [AndroidThemesGroup](AndroidThemesGroup.md) 的 140 字长 53%。** **两边都用花体字与 emoji 分隔线做装饰性排版，但这个群做得更重。**

**本语料由此在"属性检索标签"**（[AndroidThemesGroup](AndroidThemesGroup.md) 第三节确立的第八种标签用途）**上补一条方法论：颜色标签的分布可以当作社群审美偏好的定量指标，但跨社群比较时必须先确认两个社群是否连通。**

## 五、核心发现四：38 次助力请求

**`t.me/boost/` 出现 38 次，高于 [AndroidThemesGroup](AndroidThemesGroup.md) 的 25 次，而本群的成员数更少。**

**折算成人均：本群 38/16,486，上一篇 25/20,092——**本群的助力请求密度是上一篇的 1.85 倍。

**本语料在 [AndroidThemesGroup](AndroidThemesGroup.md) 第八节把 Boost 列为"不变现的第七种类型：换平台权益"。**

**这个样本让那条结论更结实：两个互不相通的主题社群，独立地把 Boost 当成了主要的"收益"形式。**

**这不是一个群的习惯，是这个品类的常态。**

**原因可以从商业结构上推出来：主题是免费的、创作者是业余的、受众地域集中在支付基础设施不便的地区**（上一篇观察到波斯语区特征）——**货币化的每一个环节都不通，而 Boost 不需要任何一个环节：它用读者已经付给平台的钱，换创作者需要的平台功能。**

## 六、实现技术思路

**零基础设施：0 个 bot、0 个自有域名、0 个服务器、0 条站外链接。**

**全部能力由平台提供**（主题安装、背景应用、标签检索、转发分发、Boost 激励），**运营者只做三件事：转发、打标签、排版。**

**与 [AndroidThemesGroup](AndroidThemesGroup.md) 完全相同，只多一个动作：上传 `.tgx-theme` 文件。**

**55 个发言人、top10 占 79%、bot 0 条**——**比上一篇更集中**（那边是 36 人 / 65%）。

**存活率 32.2% 明显低于上一篇的 63.2%。** **按本批 [ibetame](ibetame.md) 第二节确立的判据（高存活率有两种相反成因，必须看幸存内容），这里要反过来问：32.2% 是在删什么？**

**答案在数据里：广告粗筛 0/300、零站外域名、零收款、零联盟参数**——**幸存内容完全干净，而且没有任何东西指向群外。**

**结合 12.50 条/天的低吞吐（上一篇是 60 条/天），最可能的解释是：** **这个群的删除来自发布者自己撤回**（主题做废了、排版错了、重发），**而不是治理。** **本语料在 [surfboardnews](surfboardnews.md) 第四节记录过"发布撤回坏构建"这一删除成因，这是它在 UGC 场景下的对应形态。**

## 十、法律风险

**风险等级：低。**

- **主题文件本身不构成侵权。** Telegram 主题是配色与字体设置的集合，**不包含第三方美术作品。** **`.tgx-theme` 文件同理**——**它是一个配置文件，20 个合计不到 4.5 MB 的体积也印证了这一点（若含位图素材，体积会大得多）。**
- **背景图（`bg` 深链 74 次）有边界问题。** 与 [AndroidThemesGroup](AndroidThemesGroup.md) 第十节的分析相同：**背景图是图片作品，若使用了受著作权保护的图像则涉及《著作权法》第 53 条信息网络传播权。** **样本中的 `#aestheticpic` 标签 39 次与一个专门的美图来源频道（37 次引用）说明存在系统性的图片再分发**——**这一项比上一篇更明显，因为上一篇没有专门的图源频道。** **但仍属非商业的个人分享，规模远低于 [magazinesclubnew](magazinesclubnew.md)、[shareAliyun](shareAliyun.md) 那类。**
- **零商业行为。** 无收款、无广告、无推广分成、**零站外链接**——**这切断了所有需要"营利目的"要件的刑事路径，也排除了《广告法》第 14 条的适用场景。**
- **群主的管理义务：履行情况可接受。** 存活率 32.2%、0 条粗筛命中、幸存内容完全干净。**第六节已论证该删除率最可能来自发布者自行撤回而非治理**——**但结果上群内无违法内容，义务履行的结果是达标的。**
- **境内连接点：无。** 内容为英语与装饰性花体字、来源频道的命名风格与 [AndroidThemesGroup](AndroidThemesGroup.md) 同属非中文语区、**未见中文内容与中国大陆指向。** **中国法的管辖意义有限。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（219 张图片均为手机界面截图与壁纸，0 条成人内容）；不涉及帮助信息网络犯罪活动罪（零收款、零支付通道、零推广分成、零站外链接）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（零 bot、零数据收集）；不涉及提供翻墙服务（零站外域名，内容与代理无关）。

**责任主体**：群主与管理员，**身份不可见**（无管理发言、无自有 bot、无置顶可见）。**暴露面：零域名、零收款、零服务器、零站外链接**——**这是本语料暴露面的绝对下限：它在 Telegram 之外不存在。** **与 [lover_links](lover_links.md)（四条变现线各带一个身份锚点）构成本批的两个极端。**
