# moeisland · 绝对萌域

> ⚠️ 本报告不复现画师账号、作品链接与任何图像内容描述。
>
> **频道 · 21,221 订阅 · 中位阅读 424（`14–28d` 桶） · ERR ≈ 2.0% · 转发 8.9/帖（中位 8） · ER 0.92% · 12.00 条/天**
> 数据来源：`scripts/tg_recon.py dump moeisland --limit 300` → [data/recon/moeisland.jsonl](../data/recon/moeisland.jsonl)
> 抓取时间 2026-09-13 · 样本 300 条（2026-08-18 → 2026-09-13，跨度 25 天）

**一句话结论：680 个外链里 680 个指向同一家社交平台——548 个 `x.com` 加 132 个 `twitter.com`。这是一条把日文二次元画师的推文整条搬进 Telegram 的管道，每天 12 条，正文是「画师名：原文」加一个链接，中位 78 字。它顺手提供了一个对照实验：[LptTech](LptTech.md) 的 `twitter.com` 与 `x.com` 链接按 2023 年 7 月改名日期干净地分成两段、零重叠，而这个号在同一个 25 天窗口里两个域名同时存在，比例 1:4。差别在于谁生成链接——LptTech 是运营者手打（用当时的域名），这个号是转贴用户原文（用户粘什么就是什么）。同一个域名指标，在两种管道上读出完全不同的东西。**

## 二、核心发现一：同一个域名指标，两种读法

**本语料在 [LptTech](LptTech.md) 第二节确立过一条方法：`twitter.com` 与 `x.com` 的时间分布可以当作时间标尺。** 那个号的数据是：

| 域名 | 条数 | 时间范围 |
|---|--:|---|
| `twitter.com` | 35 | 2023-03 → 2023-06 |
| `x.com` | 31 | 2023-10 → 2025-02 |

**零重叠**——因为运营者每次手打链接时用的都是当时的域名。

**moeisland 的数据完全相反：**

| 域名 | 条数 | 时间范围 |
|---|--:|---|
| `x.com` | **548** | 2026-08-18 → 2026-09-13 |
| `twitter.com` | **132** | **同一区间** |

**在一个 25 天的窗口里两者并存，比例约 4:1。**

**成因是链接的生成方式不同：**

| | [LptTech](LptTech.md) | **moeisland** |
|---|---|---|
| 链接怎么来的 | **运营者手打** | **从原推文里带过来** |
| 用的是什么域名 | 当时的官方域名 | **原作者当初粘贴时用的域名** |
| 结果 | 严格按时间分段 | **长期混杂** |

**132 条 `twitter.com` 的存在，说明这些链接来自 2023 年 7 月改名之前就已经存在的推文，或者来自仍在使用旧域名的用户。**

**方法论结论：`twitter.com` / `x.com` 只有在"运营者主动生成链接"的频道上才能当时间标尺；在转贴型频道上它测的是内容的年龄分布，不是频道的年龄分布。** 本语料此前把这条方法记在 [LptTech](LptTech.md) 名下，**现在需要加上这个前提。**

## 三、核心发现二：12 条/天、ERR 2.0%，但 ER 0.92%

**这三个数字放在一起是反常的。**

| 指标 | 本号 | 解读 |
|---|--:|---|
| 频率 | 12.00 条/天 | 高 |
| ERR | ≈2.0% | **低** |
| **ER（反应/阅读）** | **0.92%** | **本语料偏高的一档** |
| 反应覆盖 | 285/300（95%） | 高 |
| 反应中位 | **4** | **极低** |

**ERR 低而 ER 高，意味着：看到的人不多，但看到的人几乎都会点一下。**

**本语料的 ER 谱系：**

| 频道 | ER | 内容类型 |
|---|--:|---|
| [thinkpositivewords](thinkpositivewords.md) | 0.86% | 励志语录 |
| **moeisland** | **0.92%** | **二次元画作** |
| [tginfoen](tginfoen.md) | 0.69% | 平台新闻 |
| [kejiqu](kejiqu.md) | 0.44% | 科技资讯 |
| [jike_collection](jike_collection.md) | 0.16% | 长文搬运 |
| [sspai](sspai.md) / [zaproshare](zaproshare.md) | 0.03% | 链接/资源 |

**排在前两名的是语录和画作——两类"看一眼就能产生情绪"的内容。** 排在末尾的是链接和资源——**"看完要去做别的事"的内容。**

**这条规律在本语料至此可以明确表述：ER 由"内容能否在原地引发反应"决定，与内容质量、频道规模、频率都无关。**

**反应中位只有 4 是另一面：12 条/天摊薄了每条的注意力，所以绝对值很低，但比例很高。** **这是"高频摊薄"在 ER 与 ERR 上的不同表现——ERR 被摊薄了，ER 没有。**

**原因是分母不同**：ERR 的分母是订阅数（固定），ER 的分母是阅读数（也被摊薄了）。**摊薄同时压低了分子和分母，比值因此不变。** **本语料此前一直用 ERR 讨论高频摊薄，这里第一次说清楚为什么 ER 不受影响。**

## 四、核心发现三：95% 单平台依赖

**680/712 个外链（95%）指向同一家社交平台。** 其余 32 条分散在：视频平台（9+2）、图床（7）、插画平台（6）、约稿平台（2）、同人商品平台（2+1）、以及几个单次出现的官方站。

**这是本语料单平台依赖度最高的样本。** 对照：

| 频道 | 最高单域名占比 |
|---|--:|
| **moeisland** | **95%**（一家社交平台） |
| [sspai](sspai.md) | 100%（自家站） |
| [hacker_news_feed](hacker_news_feed.md) | 95%（自家短链） |
| [kejiqu](kejiqu.md) | 62%（一家中文科技站） |
| [jike_collection](jike_collection.md) | 48%（一个社交 App） |

**但 [sspai](sspai.md) 和 [hacker_news_feed](hacker_news_feed.md) 的 100%/95% 指向的是自己的资产，本号的 95% 指向的是别人的平台。** **这是完全不同的风险结构：前者是封闭，后者是依赖。**

**单点依赖的具体后果可以列出来：**

1. **平台的 API 或防爬策略一变，管道就断。**
2. **平台的可访问性决定了这个频道的价值**——如果读者能直接刷那个平台，这个频道就没有存在理由。**它的 2.1 万订阅本身就说明相当一部分读者访问那个平台有困难。**
3. **图片是热链还是转存不可观测**，但托管文件只有 3 个（1.1 MB），**说明图片走的是 Telegram 的网页预览抓取或直接上传，而不是本地托管。**

**内容结构：`<画师名>: <原文>` + 链接，中位 78 字。** 标签是日文的作品名与活动标签（某几个手游 IP 各 3–5 次、某绘师活动标签 3 次、某约稿平台标签 3 次），**分布极度分散——15 个标签里最高只出现 5 次**，说明**没有标签体系，只是把原推文的标签带了过来。**

**自动化程度：中高。** 间隔中位 226 秒（3.8 分钟）、`<60 秒` 占 16%；**无 cron 指纹（分钟/秒随机）**，但 12 条/天的稳定输出加上格式统一，**判断是"订阅若干画师账号 → 有新作就转"的事件驱动管道。**

## 五、实现技术思路

```
订阅一批二次元画师的社交平台账号
      ↓  事件驱动（有新作就触发）
抓取图片 + 作者名 + 原文
      ↓
套模板：<画师名>: <原文> + 原帖链接
      ↓
发布（间隔中位 3.8 分钟，不成批）
```

**没有任何加工**：不翻译（日文原文照搬）、不整理标签、不写评论、不做分类。

**互动配置：反应开、评论关。** 反应覆盖 95% 说明读者愿意点，**评论关闭是这类频道的常规选择**——画作没有可讨论的对象，而开评论会引来对内容来源的质疑（见第九节）。

**删除率 2.6%** 很低。对一个搬运他人作品的号，**这说明它几乎没有收到过删除要求**——**在日文二次元圈，画师对转载的态度差异很大，但主动追到 Telegram 上来的极少。**

**托管文件只有 3 个共 1.1 MB**（都是短动图），**297 张图片全部不在本地**。**这是一个刻意或偶然的减责设计**：如果图片是通过网页预览抓取的，**那么"复制件"在技术上不存在于这个频道里。** 本报告无法确认具体实现，**但托管量与图片数的巨大落差是事实。**

## 六、成本

**一次性**

| 项目 | 金额 | 依据 |
|---|--:|---|
| 抓取管道开发 | ¥2,000–8,000 | 订阅多账号 + 抓取 + 格式化 + 发布，1–4 人日 |

**经常性（月）**

| 项目 | 金额 | 依据 |
|---|--:|---|
| VPS | ¥20–100 | 轻量抓取 |
| **平台访问成本** | **¥0–300** | 见下 |
| 人力 | **¥0–300** | 选画师、偶尔修管道 |

**经常性合计 ¥20–700/月。**

**"平台访问成本"是这个号特有的一项。** 目标平台对高频抓取有速率限制，**持续订阅数十个账号通常需要：一个付费的 API 档位、或一批代理 IP、或若干个账号轮换。** 本报告无法确认它用的是哪种，**三种的成本从 0（用公开接口 + 低频轮询）到几百元（付费 API）不等。**

**人力接近零。** 360 条/月（12 × 30）全部是自动产出，**人只需要维护画师订阅列表——而画师列表一旦定下来，几个月不用动。**

**这是本语料成本最低的高频号之一。** 对照 [hacker_news_feed](hacker_news_feed.md)（30 条/天、¥60–410/月）、[kejiqu](kejiqu.md)（3.12 条/天、¥25–740/月）——**三个号都是纯管道，成本都在三位数以内。**

## 七、收益

**¥0。25 天、300 条、0 条广告、0 个联盟参数、0 个收款入口、0 次自我推广。**

**32 条非主平台链接里有 2 条指向约稿平台、3 条指向同人商品销售页**——**但那些是画师自己在原推文里贴的，不是这个号加的。** **本号没有在任何一条链接上添加过参数。**

**这一点值得单独确认：URL 参数统计只有 `name` 7、`category_id` 1、`si` 1**——**全部是原链接自带的，没有一个是联盟或追踪参数。** 对照 [hacker_news_feed](hacker_news_feed.md)（100% 换成自有短链）、[BaccanoSoul](BaccanoSoul.md)（374 个联盟短链）——**这个号连改链接的动作都没做。**

**未变现的承载力：**

- 月曝光 = 12 × 30 × 424 ≈ **15 万次**
- **受众是中文二次元用户**，在中文 TG 广告市场属中等价位；**能对口的广告主是手游、同人展会、周边电商**
- **但单帖阅读只有 424**，广告主买单条位置的意愿很低

**按每月 4–8 条、单条 ¥80–300 计：¥320–2,400/月。**

**区间宽的三条原因：**

1. **单帖阅读 424 太低**——**这是最硬的约束。** 一个 2.1 万订阅的号，单帖只有 424 人看，**广告主会直接按阅读数议价，而不是按订阅数。**
2. **12 条/天意味着广告会被迅速冲走**（与 [PublicTestGroup](PublicTestGroup.md) 第七节的"流式版面"问题同理，但这是频道，情况稍好）。
3. **内容全是他人作品**，正规广告主会顾虑品牌安全。

**趋势：无法判断。** 25 天窗口、无成熟帖。**这是本语料第四个因高频导致窗口过短的样本**（前三个是 [hacker_news_feed](hacker_news_feed.md) 10 天、[BaccanoSoul](BaccanoSoul.md) 2 天、[jin10light](jin10light.md) 2 天）。

## 八、增长策略

| 机制 | 证据 | 判读 |
|---|---|---|
| **访问替代** | 95% 链接指向一个在部分地区难以直接访问的平台 | **核心价值** |
| 高频 | 12 条/天 | 覆盖面 |
| 保留画师署名 | `<画师名>:` 开头 | 降低侵权争议 |
| 附原帖链接 | 680 条 | 可溯源 |
| 互推 | **0** | 零第三方 `t.me`、零 @ 自家 |
| 买粉 / 刷互动 | **无从判断** | CV 样本不足；反应中位仅 4 |

**2.12 万订阅的来源只有一条：它把一个访问不便的平台上的内容搬到了一个访问相对方便的地方。**

**这与本语料的 [surfboardnews](surfboardnews.md)（把代码托管平台的 APK 直接放进 Telegram）、[LptTech](LptTech.md)（把 219 MB 演讲视频重新上传）是同一种价值主张：消除访问摩擦。**

**三者的区别在于摩擦的性质：**

| 频道 | 消除的摩擦 |
|---|---|
| [surfboardnews](surfboardnews.md) | 代码托管平台访问不稳 + 链接可能失效 |
| [LptTech](LptTech.md) | 需要翻墙 + 下载 + 可能失效 |
| **moeisland** | **需要翻墙 + 需要自己关注几十个账号** |

**第三项"需要自己关注几十个账号"是这个号独有的附加值**——**即使读者能访问那个平台，他也未必知道该关注谁。** **策展本身就是价值，哪怕策展动作只是"把订阅列表公开化"。**

**它没有任何主动获客动作**：零互推、零标签体系、零自我推广、连页脚署名都没有。**在本语料里，"完全零获客动作"的号只有 [ruheyushadiaoxiangchu](ruheyushadiaoxiangchu.md)（2.88 万订阅）和这个。**

## 九、法律风险

**风险等级：中。** 唯一的实质问题是未经授权转载画师作品，而这一项的实际追究概率取决于圈层规范而非法律条文。

- **美术作品的著作权（主要风险）。** 297 张图片是二次元画师的原创作品，**受《著作权法》第 3 条保护（美术作品）**，转载需要授权。本号**未获授权、未标注授权状态**。
  - **减轻情节有两项，都很实在**：**保留了画师署名**（正文以 `<画师名>:` 开头，300 条中 286 条有正文）、**附了原帖链接**（680 条，可溯源）。这两项使它区别于本语料的 [ruheyushadiaoxiangchu](ruheyushadiaoxiangchu.md)（150 个视频，保留话题标签但不保留作者署名）。
  - **加重情节是规模与系统性**：25 天 297 张，**这是一条持续运行的自动化管道，不是零星转发。**
  - **一个技术性的减轻因素**：托管文件只有 3 个共 1.1 MB，**297 张图片不在本频道的存储里**。若图片确实是通过网页预览机制呈现的，**则"复制件"在技术上不存在**，侵权定性会显著减轻（从"复制+传播"变成"提供链接"）。**本报告无法确认实现方式，但这一点在争议中会是关键事实。**
- **二次创作作品的双层权利。** 样本中的标签显示大量内容是对商业 IP 的同人创作（某几个手游、某虚拟主播企划）。**这类作品本身就处在原 IP 权利人的授权边界上**——画师对自己的表达有著作权，**但对角色形象没有。** 转载这类作品，**理论上同时牵涉画师与原 IP 两方，实务上原 IP 方极少追究非商业同人。**
- **约稿与商品链接的转载。** 32 条非主平台链接中有约稿平台与同人商品销售页。**这些是画师自己的商业入口，本号原样带过来，实际上是在帮画师导流。** 这一项对画师有利，**在侵权争议中是一个有力的抗辩材料。**
- **平台服务条款。** 系统性抓取并再分发该平台的内容，**通常违反其自动化访问与内容再分发条款。** 这是运营者与平台之间的合同关系，**与画师的著作权主张是两条独立路径。**
- **删除率 2.6% 的含义。** 几乎不删说明**没有收到过删除要求**。**这对"通知—删除"免责规则是中性的**——规则要求的是"收到通知后删除"，**而不是"主动删除"。** 与本语料的 [yeqingjie_GJG666](yeqingjie_GJG666.md)（5.4%，同样几乎不删，但内容是商业影视）相比，**本案的权利人是分散的个人画师，主动维权的成本远高于影视公司。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（**样本中出现的作品标注为 SFW 类型，未见成人内容；标签体系与画师构成也指向一般向创作**）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流，25 天零商业行为）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（无个人信息处理；画师账号名是其公开的创作署名，不属于个人信息保护法意义上的敏感信息）。

**责任主体**：管道运营者。**暴露面极小**——零域名、零收款、零自建站、零 bot、零第三方 `@`、托管量仅 1.1 MB。**唯一的技术痕迹是它抓取时使用的账号或 IP，而那只有目标平台看得到。** 对照 [yeqingjie_GJG666](yeqingjie_GJG666.md)（七个实名网盘 + 域名 + 服务器 + 两个 bot）——**同样是搬运，不落地就不留痕。**
