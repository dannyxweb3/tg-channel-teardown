## 二、核心发现：五频道分品类矩阵

**每一条消息的正文底部都固定挂着同一行导航：**

```
[精选新闻] · [软硬件技术] · [互动娱乐] · [商业产业] · [趣闻八卦]
```

对应的 t.me 目标各出现 **223 次**（300 条中的 223 条带完整 footer）：

| 子频道 | 引用次数 | 品类 |
|---|---|---|
| `cnbeta_com` | 223 | 总频道（精选） |
| `cnbeta_com_tech` | 223 | 软硬件技术 |
| `cnbeta_com_media` | 223 | 互动娱乐 |
| `cnbeta_com_business` | 223 | 商业产业 |
| `cnbeta_com_buzz` | 223 | 趣闻八卦 |

**这是一套"总频道引流 + 分频道承接"的分发架构**：总频道只发精选（3.67 条/天，避免刷屏劝退），想看某品类全量的用户被导流到对应子频道。t.me 引用累计 **1,115 次**，全部指向自家矩阵——**零外部导流、零互推**。

**代价是转发率低（4.2/帖）**：每条都带着一长串导航 footer，转发出去显得像广告；而且新闻本身的转发意愿本就低于工具类内容。

## 三、内容与技术

**3.1 纯管道，无编辑加工**

- **300/300 条全部是 `MessageMediaWebPage`**（链接预览卡），无一例外
- 正文中位 **70 字、3 行**——就是"标题 + 导航 footer"
- 外链 `www.cnbeta.com.tw` **300 次**，全部导回母站

注意域名是 **`.com.tw`**——cnBeta 原 `.com` 域名已不再使用，现运营在台湾域名下。这是一个值得记录的事实：**老牌中文科技站的运营主体已迁出大陆**。

**3.2 发布节奏：半自动，跟随母站发稿**

小时分布覆盖全天，8 点（55 条）为明显高峰，其次 15–16 点（47 条）、7 点（22）。分钟与秒**无固定值聚集**，间隔中位 7,264 秒。

**这不是固定 cron，是跟着母站发稿节奏走的推送**——母站编辑发稿后同步到 TG。`<60 秒` 间隔只占 6%，说明很少批量连发，是一条一条推。

**3.3 选题：什么在中文科技读者里能爆**

阅读与转发榜单高度一致，集中在三类：

| 类型 | 例子 | 数据 |
|---|---|---|
| 国内互联网politics/合规 | 豆包、千问将下线智能体功能 | 4,122 阅读 |
| **消费者权益争议** | 跨境自驾新能源车突遭远程锁车 30 小时 | **34 转发**（最高） |
| | 蔚来 APP 大规模闪退 车主"集体罚站" | 21 转发 |
| | 打工人把星宇批量劝退捅给了大众奔驰 | 25 转发 |
| 社会奇案 | 三体公司原 CEO 投毒案细节披露 | 3,405 阅读 / 21 转发 |

**转发榜前三全是"用户被企业坑"的消费者权益类新闻。** 这与 GodlyNews1 的规律一致：**触及切身利益的内容扩散最快**，只不过 GodlyNews1 的读者关心的是订阅涨价与免费额度，cnbeta 的读者关心的是国内车企与雇主。

**TG 频道不直接变现，它的经济价值是给母站导流。** cnBeta 母站的商业模式是传统的资讯站广告位，TG 这 2.75 万订阅每天贡献约 3.67 条推送 × 1,769 阅读 ≈ 6,500 次曝光，其中一部分转化为母站 PV。

**按导流价值折算**：若 10–25% 的阅读者点击进入母站，日均带来 650–1,600 PV；按中文资讯站 CPM ¥10–30 折算，**约合 ¥200–1,400/月的母站广告收入**。这是一个很小的数字——**对 cnBeta 这个体量的站点，TG 渠道更多是品牌存在感与用户触达，而非收入来源。**

**趋势**：阅读中位 2026-07 的 2,034 → 08 月 1,835 → 09 月 1,390，**连续两个月下滑**。6 月的 655 因样本少且时间早需排除。转发同步从 5 降到 3。**短期呈温和衰减。**

## 六、增长

`paid_acquisition: none`。

| 机制 | 证据 | 判读 |
|---|---|---|
| 母站品牌 | 二十余年老牌资讯站 | 频道靠品牌自然沉淀 |
| 五频道矩阵分流 | 每条挂 4 个子频道，累计 1,115 次引用 | 用分品类承接不同兴趣，降低总频道刷屏感 |
| 精选策略 | 总频道仅 3.67 条/天 | 克制推送以保留订阅 |
| 零外部依赖 | 无互推、无买粉、无 bot、无 @提及 | 完全自然 |

**它不做增长，只做留存。** 五频道矩阵的设计目的很明确：**让高频用户去子频道，让低频用户在总频道不被打扰**——这是资讯站在 IM 渠道上的标准分发解法。
