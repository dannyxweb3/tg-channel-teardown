## 三、抽奖机制与自动化

**3.1 用的是第三方抽奖 bot**

样本内的抽奖帖是机器生成的结构化文本：

```
新的抽奖已经创建
抽奖 ID：d219def9-c48a-4658-928e-1b948bcab2b9
创建者：青木蚂蚁 🐜🐜🐜 (224464442)
抽奖创建时间：2025-01-30 09:39:17
参与设置   允许普通用户参加：是   允许频道参加：否
开奖方式：条件开奖   自动开奖时间：2025-02-01 09:38:00+08:00
```

**UUID 格式的抽奖 ID、创建者的数字 user id、精确到秒的时间戳——这是一个通用抽奖 bot 的标准输出。** 转发来源统计里「抽奖机器人」出现 24 次，证实了这一点。

开奖帖会给出真实概率：

> 当前中奖概率：30/179 = 16.76%

**16.76% 的中奖率相当高**（179 人抢 30 份），**这是维持 ERR 25% 的直接原因——参与不是白参与。**

**3.2 规则设计有反羊毛党条款**

> 🔴 无用户名用户中奖无效
> 🔴 活动展开期间禁止加群
> 🔴 不能私聊请自行解决且不作为超越领奖限制的理由

**"无用户名用户中奖无效"** 是过滤新注册小号；**"活动期间禁止加群"** 是防止临时涌入的羊毛党；**"不能私聊请自行解决"** 把 Telegram 隐私设置的锅推给用户。

**三条规则合起来说明它被薅过，而且吃过亏。**

**3.3 转发构成：它是一个中枢**

126 条来自转发（42%），来源分布：

| 来源 | 次数 | 性质 |
|---|--:|---|
| 青木蚂蚁 🐜🐜🐜 | 35 | **运营者本人账号** |
| 抽奖机器人 | 24 | 抽奖 bot |
| Infuse News / Infuse Tips | 14 + 7 | 单个 App 的官方频道 |
| APTV 通知频道 | 6 | 同上 |
| 自力 hzlzh | 6 | 开发者个人号 |
| DS One 发布会 / Conflux News | 5 + 3 | |

**它把散落在各个 App 官方频道的更新公告聚合到一处**，同时用自己的账号补充点评。**这是一个人工策展的聚合器，不是脚本。**

**3.4 节奏：完全手工**

```
小时：9 点 51 条（17%）、22 点 35、13 点 24、17 点 23、0 点 19
分钟最高 :15 仅 19 次 | 秒最高 :34 仅 20 次
间隔中位 18,112 秒（5 小时），<10 秒占 32%（成组转发）
```

**分/秒无任何聚集，零 cron 痕迹。** 9 点与 22 点两个小高峰是运营者自己的作息。

## 五、成本

**5.1 一次性启动成本**

| 项 | 估算 | 说明 |
|---|---|---|
| 建频道 + 群 | ¥0 | |
| 抽奖 bot | ¥0 | 用的是现成的第三方通用 bot |
| **开发者关系** | **不可计价** | **真正的门槛在这里** |
| **合计** | **¥0** | |

**它的启动成本在钱上是零，在信任上极高。** 十几个 iOS 独立开发者愿意持续免费送出终身授权码，**这需要长期的口碑积累——两年 300 条的运营历史本身就是那份资产。**

**5.2 经常性成本**

| 项 | 估算 | 说明 |
|---|---|---|
| 策展 + 联络开发者 | 15–30 小时/月 | 挑 App、写推荐、谈奖品、办活动 |
| 抽奖执行与发码 | 5–15 小时/月 | 中奖者要私聊领码、核验规则、处理纠纷 |
| bot / 托管 | **¥0** | 全部用现成设施 |
| **现金合计** | **¥0/月** | |

**这是一个纯人力驱动的号，现金成本是零。** 但"发码"这一环的时间成本容易被低估——**"零点前承兑，过时不候"这句话意味着运营者要在特定时间窗口内手工处理几十个私聊。**

**若按现金折算它的商业价值**：8,492 订阅、中位阅读 2,168、ERR 25.54%。**iOS 工具类是中文 TG 里付费意愿最高的受众之一（愿意为 App 花钱），CPM 可达 ¥100–250。** 按每月 14 条推送（0.47 条/天）计，月曝光约 3 万次：

> **月度广告承载力约 ¥3,000–7,500。**

**区间宽的三个原因**：(1) 无任何报价信息；(2) **它的曝光量小但质量极高，ERR 25% 的受众定价可以远高于 CPM 均值，也可能因为总量太小而根本卖不出去**——这两种可能样本无法区分；(3) 640 天的样本跨度里，商业形态可能已经变过。

**一个值得注意的取舍**：它有本轮最好的用户质量，却选择完全不收现金。**原因很可能是收了现金就要接非 iOS 工具类的广告，而那会立刻破坏"这个号推荐的东西都值得抢"的信任——那份信任正是开发者愿意免费送码的前提。它在保护自己唯一的资产。**

## 八、法律风险

> **level: medium。**
>
> **1｜抽奖活动合规（主要项）。** 中国大陆《反不正当竞争法》第十条规定有奖销售的最高奖金额不得超过五万元；《规范促销行为暂行规定》要求公示奖项设置、开奖方式、兑奖条件。本频道的抽奖**公示做得相当完整**（奖品清单、中奖概率 30/179、开奖时间、参与规则均明示），单份奖品价值最高约 ¥600（Infuse 终身），远低于五万元上限。**但它的规则里有"零点前承兑，过时不候""无用户名用户中奖无效"等对中奖人不利的条款，若发生纠纷，这类单方设定的失权条款效力存疑。** 责任主体为活动组织者。整体风险很轻。
>
> **2｜奖品中包含代理工具与"机场"订阅。** 样本内一次抽奖的奖池里出现「**神秘机场 × 3**」，另有 Pharos pro（支持 mieru / anytls 协议的代理客户端）与 StashLink（内网穿透代理）作为推荐内容。中国大陆《计算机信息网络国际联网管理暂行规定》第六条禁止自行建立或使用其他信道进行国际联网；情节严重的可依《刑法》第二百八十五条**提供侵入、非法控制计算机信息系统程序、工具罪**追究，实践中对"机场"经营者的判例多以**非法经营罪**处理。**本频道是推荐与转赠方，不是经营方，责任层级明显低于机场运营者**，但"赠送机场订阅"这一行为已越过单纯的软件推荐边界。**这是本频道唯一实质性的风险点。**
>
> **3｜著作权与商标。** 转发各 App 官方频道的更新公告、使用 App 图标与截图，属于推荐语境下的合理引用，且多数内容经开发者本人同意（他们在送奖品），风险可忽略。
>
> **不适用的两条**：不涉及帮助信息网络犯罪活动罪与开设赌场罪——样本内 0 个收款账号、0 条博彩导流、0 条诈骗要素；"抽奖"是免费参与、无投注、无对价，与射幸性赌博在法律构成上没有交集。
