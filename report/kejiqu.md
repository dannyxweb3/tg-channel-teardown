## 二、核心发现一：管道没重写过链接，所以上游的追踪参数还在

300 条帖的外链里出现了两种本不该同时出现的参数：

```
?utm_source=rss1.0mainlinka        ← 出现在 slashdot 系链接上
?sid=84590                          ← 出现在 solidot 链接上
```

**`rss1.0mainlinka` 是 Slashdot 自己 RSS 输出里带的来源标记，用来区分订阅渠道。** 它出现在 kejiqu 的帖子里，只能说明一件事：**这条链接从 Slashdot 的 RSS feed 里读出来之后，一个字符都没改就发了出去。**

本语料里的"链接归属"谱系因此多了一档：

| 频道 | 链接处理 | 含义 |
|---|---|---|
| [theblockbeats](theblockbeats.md) | 300/300 带自有 `from` 参数 | **主动归因** |
| [merlinclashcat](merlinclashcat.md) | 带联盟 `aff` 参数 | 主动变现 |
| [sspai](sspai.md) | 裸链，零参数 | 不归因 |
| **kejiqu** | **带的是上游 RSS 的参数** | **连处理都没有** |

**"没有归因"和"连上游参数都没清"是两件事。** 后者说明管道里不存在任何 URL 处理环节——没有加 UTM，也没有去 UTM。这是判断自动化流水线是否粗糙的一个新指标。

顺带：12 条双外链帖的配对方式暴露了信源结构——`solidot.org/story?sid=` 配 `nature.com`、配 `cn.nikkei.com`、配 `zaobao.com.sg`，`slashdot` 配 `finance.yahoo.com`。**它在给出中文转述的同时给出一次原始信源**，这在本语料的聚合号里不常见（[times001](times001.md) 就从不给原始信源）。

## 三、核心发现二：标签是机器切的，切词把信源站名也切进去了

标签行的样本：

| 标签行 | 被切开的原词 |
|---|---|
| `#Sensor #Tower #中国手游 #全球收入` | Sensor Tower（数据机构名） |
| `#逆时针行走 #biomechanics #Nature #Communications` | Nature Communications（期刊名） |
| `#iOS #Apple #Intelligence #Android` | Apple Intelligence（产品名） |
| **`#Google #Earth #Flight #simulator #Android #Authority`** | **Google Earth Flight simulator + Android Authority（信源站名）** |

**最后一条是决定性的。** `Android Authority` 是这条新闻的**来源媒体**，不是新闻内容里的任何实体。它出现在标签行里，只能解释为：**喂给标签生成环节的不是正文，是整条抓取记录——标题、正文、来源站名一起进去了。**

而所有这些切分都发生在**空格**处。中文标签（`#中国手游`、`#全球收入`、`#逆时针行走`）完整无损，英文多词专名无一幸免。

**本语料的"分词切开标签"误报谱系至此有了第二个样本**，且两个样本的成因不同：

| 样本 | 现象 | 成因 |
|---|---|---|
| 早期批次 | `#Open` + `#AI` | tokenizer 把 OpenAI 拆了 |
| **kejiqu** | `#Sensor` + `#Tower` | **按空格切多词专名** |

前者是子词切分，后者是空白切分——**遇到 `#Open #AI` 要想到 tokenizer，遇到 `#Sensor #Tower` 要想到 `split()`。**

**正文本身是 LLM 改写的，不是原文复制。** 证据：结构 300/300 完全一致（标题行 → 空行 → 一段 200–400 字摘要 → 空行 → 🏷 标签行 → 页脚），摘要里保留了具体数字和公司名但句式被统一过，且段尾用裸词标注来源（如正文末尾直接写站名）。**一个纯 RSS 转发脚本做不到这种改写，一个纯人工编辑做不到 300/300 的结构一致性。**

## 四、核心发现三：本语料刻度最细的"三周饱和"曲线

帖龄分桶：

| 帖龄 | n | 中位阅读 | **占最终值** |
|---|--:|--:|--:|
| 3–7 天 | 4 | 1,211 | **33%** |
| 7–14 天 | 25 | 2,063 | **57%** |
| 14–28 天 | 50 | 3,050 | **84%** |
| 28–56 天 | 90 | 3,581 | **98.4%** |
| ≥56 天 | 131 | 3,638 | **100%** |

**28 天到 56 天只涨了 1.6%，56 天之后可以认为完全停止。**

本语料的"三周饱和"此前由 [solidot](solidot.md)、[sspai](sspai.md) 两个样本确立。kejiqu 是第三份独立验证，而且它的样本量分布最好（四个桶都有 25–131 条），**第一次把曲线的刻度给出来了**：

- **第 14 天拿到 57%**
- **第 28 天拿到 84%**
- **第 56 天拿到 98%**

**实务含义：用 `≥56 天` 作为成熟阈值是保守的，`≥28 天` 已经足够（误差 1.6%），而 `≥14 天` 会低估 43%。** 本语料此前对 `14–28d` 桶的数据一向持保留态度，现在可以说得更准：那个桶的数字大约是最终值的 84%，可以用，但要标注。

这三个号的共同点值得一提：都是**中文科技新闻**、都是**日更或高频**、订阅量在 3.6 万–4.7 万。**曲线形状在这个类目里稳定，不代表对成人向号（见 [sizukon](sizukon.md)，三年后仍在涨）或大号（见 [XPlus_Channel](XPlus_Channel.md)）同样成立。**

## 五、核心发现四：23 条"疑似广告"全是误报，且 19 条出自同一个词

粗筛命中 23 条（8%）。逐条看：

| 命中词 | 条数 | 实际语境 |
|---|--:|---|
| **合作** | **14** | 「UCSD 与谷歌**合作**」「中美**合拍**」「联合推出」——全部是新闻正文里的公司协作 |
| 联系 | 3 | 「未经同意的电话营销」「绝不会泄露隐私」类报道 |
| 广告 | 2 | 「YouTube 统一观看次数口径」「MiniMax 发布模型」 |
| 推广 | 2 | 「Cloudflare 为 1.1.1.1 瘦身」「Cybercab 电机」 |
| 商务 | 1 | 「贸易黑名单」报道 |
| **代理** | **1** | **「住宅**代理** Residential proxy」——三星电视被曝内置代理 SDK** |

**23 条里 0 条是广告。** 300 条消息里没有任何一条商业推广——没有联盟参数、没有优惠码、没有 bot 深链推广载荷、没有第三方商业域名。

**这让本语料的关键词误报类型增加到第 12 类，而且它是最"干净"的一类**：前 11 类多少还有语义相关性（[appinn](appinn.md) 讨论广告拦截、[tginfo](tginfo.md) 报道 Telegram 广告业务、[times001](times001.md) 报道"广告害死人"），**而 kejiqu 的 14 次命中全部来自"合作"这一个词在中文商业新闻里的常规用法。**

**方法论结论：`合作` 这个词对中文科技新闻类频道的广告粗筛毫无判别力，应当从该类目的关键词表里移除。** 「住宅代理」那一条则提醒：技术新闻里的 `代理` 是 proxy，不是 agent/经销商。

## 六、实现技术思路

**完整管道：**

```
多源 RSS 抓取  →  LLM 改写（标题 + 200–400 字摘要 + 标签）  →  配图  →  套模板  →  发布
                     ↑ 喂进去的是整条记录（含 source 字段）
```

**信源结构（按出现帖数）：**

| 信源 | 帖数 | 占比 |
|---|--:|--:|
| **某中文科技站** | **185** | **62%** |
| [solidot](solidot.md) | 21 | 7% |
| the-decoder.com | 14 | 5% |
| theregister.com | 12 | 4% |
| bloomberg / theverge | 各 9 | 各 3% |
| slashdot 系（4 个子站） | 12 | 4% |
| 其余（scitechdaily、androidauthority、nikkei 中文、9to5mac、arstechnica、zaobao、x.com、github…） | 约 38 | 13% |

**62% 单源依赖是这条管道最大的结构性弱点。** 对照 [solidot](solidot.md) 本身（二十余个信源域名）——kejiqu 把 solidot 也当成一个信源，**等于站在一个聚合器的下游再聚合一次**。

**发布节奏：事件驱动，不是定时。** 分钟 top1 占 5%、秒 top1 占 4%，没有任何 cron 指纹；间隔中位 18,649 秒（5.2 小时），`<60 秒` 仅 5%。小时分布 UTC 0–2 占 35%（北京时间 08:00–10:00）、UTC 23 占 9%、UTC 7–9 占 24%。**这个分布是信源站的发稿节奏，不是频道的排期**——与 [sspai](sspai.md) 的情况相同（sspai 的小时峰值反映的是少数派编辑部的作息）。

**与本语料其他 cron 号的对比：**

| 频道 | 调度形态 | 指纹 |
|---|---|---|
| [sspai](sspai.md) | 每小时轮询 | 分钟 `:20` 100% |
| [solidot](solidot.md) | 每 5 分钟 | 分钟 mod 5 = 0，92% |
| [theblockbeats](theblockbeats.md) | 每分钟 | 秒 `:02` 86% |
| **kejiqu** | **事件驱动，无固定周期** | **无** |

**页脚：`🏷 <标签> / 📢 频道 👥 群组 📝 投稿`，300/300 零例外。** 三个 `t.me` 链接各出现 300 次——频道自身、讨论群、投稿 bot。

**三件套矩阵的实际效果很差。** 群的证据是评论数：300 帖里只有 54 帖有评论，合计 83 条，中位 1 条，最高 4 条。**平均每 3.6 帖才有 1 条评论。** 对照 [tginfo](tginfo.md) 的 35,942 条评论——同样是"频道 + 群"结构，差了三个数量级。**投稿 bot 的使用情况完全不可观测**（没有任何一条帖标注"读者投稿"）。

**配图 298/300。** 每条新闻都配图，而正文是 LLM 改写的——图大概率也是从信源页面抓的。这带来一个在第十节讨论的版权问题。

## 七、成本

**一次性**

| 项目 | 金额 | 依据 |
|---|--:|---|
| 管道开发（RSS 抓取 + LLM 改写 + 配图 + 发布） | ¥3,000–12,000 | 2–6 人日，标准件 |
| 频道 + 群 + bot 建立 | ¥0 | |

**经常性（月）**

| 项目 | 金额 | 依据 |
|---|--:|---|
| VPS | ¥20–80 | 轻量级轮询 + 发布 |
| **LLM 调用** | **¥5–60** | 见下 |
| 人工审核 | ¥0–600 | 见下 |

**经常性合计 ¥25–740/月。**

**LLM 成本可以算得比较实：** 3.12 条/天 ≈ **95 条/月**。每条的输入是原文（科技新闻正文通常 800–2,500 字，约 1,200–4,000 token）加提示词，输出是标题 + 摘要 + 标签（约 400–600 token）。按小尺寸模型的常见价位（输入约 ¥2/百万 token、输出约 ¥8/百万 token）：

```
95 × (3,000 输入 × 2/1e6  +  500 输出 × 8/1e6)  ≈  ¥0.95/月
```

**即便换成中档模型（贵 10–20 倍），也只有 ¥10–20/月。** 区间给到 ¥5–60 是为了覆盖重试、抓取失败重跑、以及可能存在的多轮改写。

**这是本语料里 LLM 成本第一次成为可算项而不是猜项**，因为管道形态（每帖一次改写）和帖量都是已知的。**结论是：LLM 改写在这个量级上的成本可以忽略——它比 VPS 还便宜。**

**人力投入：每月 0–5 小时。** 给 0 的理由是整条链路都能全自动；给 5 小时的理由是配图选择、信源增减、以及偶尔的事实错误处理需要人看一眼。**但样本里没有任何证据表明有人在看**——300 条帖里没有勘误、没有补充、没有编辑痕迹，`#Sensor #Tower` 这种明显的切词错误从 6 月一直错到 9 月没人改。**倾向判断：人力接近 0，管道处于无人值守状态。**

对照 [tnews365](tnews365.md)（有 `#勘误` 标签、0.7% 删除率，说明有人在盯）——kejiqu 的 1.0% 删除率看着接近，但性质相反：tnews365 是"发现错就改"，kejiqu 是"没人发现"。

## 八、收益

**当前直接收入：¥0。** 300 条 0 广告、0 联盟参数、0 优惠码、0 推广载荷、0 第三方商业域名。这条证据充分。

**广告承载力（未变现的潜力）：**

判断依据：

1. **月曝光** = 3.12 条/天 × 30 × 3,638 中位阅读 ≈ **34 万次**。
2. **类目溢价**：AI / 科技类受众在中文 TG 广告市场属于中高价位（标签统计里 `#AI` 38、`#OpenAI` 31、`#Anthropic` 14、`#Gemini` 14，是明确的 AI 垂直），比泛资讯号高。
3. **本语料的横向锚**：同为中文科技资讯、订阅量相近的号，单条软广报价区间在 ¥150–600。

按每月发 4–8 条软广计：**¥600–4,800/月。**

**区间为什么宽，三条：**

1. **转发中位只有 6。** 广告主看重的是扩散而不只是阅读，3.6 万订阅只换来 6 次转发，议价能力会被压。
2. **评论 83 条说明社区不存在。** 有群但群不活，这在报价时是减分项——广告主无法在群里做二次触达。
3. **内容全是改写的第三方新闻，没有品牌人格。** 读者认的是新闻本身，不是这个号；这类号的广告转化通常低于有作者人格的号。

**最重要的一条判断：这个号目前没有在变现，而且看起来不打算变现。** 依据是第七节的结论——管道无人值守、切词错误三个月没人改。**一个准备接广告的号不会让自己的标签行一直挂着 `#Android #Authority`。**

**趋势：平稳，无增长也无衰退。** 月度中位阅读 2026-06 = 3,481、07 = 3,865、08 = 3,460、09 = 2,413（未成熟），96 天内没有任何趋势。月度转发总和 507 / 661 / 765 / 236，同样平稳。

## 九、增长策略

| 机制 | 证据 | 判读 |
|---|---|---|
| 高频稳定供给 | 3.12 条/天、96 天无断更 | **主要机制** |
| 垂直标签 | `#AI` 38、`#OpenAI` 31、`#Anthropic` 14 | 明确的 AI 垂直定位 |
| 三件套页脚 | 频道/群/投稿 bot，300/300 | 形式完备，**实效接近零** |
| 给出原始信源 | 12 条双外链，中译 + 原文 | 提升可信度 |
| 每帖配图 | 298/300 | 提升信息流点击 |
| 互推 | **0** | 零第三方 @、零第三方 t.me |
| 买粉 / 刷互动 | **可排除** | **CV 中位 0.943** |
| 矩阵 | 自有三件套，无外部矩阵 | |

**买粉与刷互动可以明确排除。** 反应向量的变异系数中位 0.943，最低的五个也在 0.417–0.614——这是自然的幂律分布形态。对照 [syfhhbd](syfhhbd.md) 的 CV 中位 0.114（向量形如 `[419,404,399,383,373]`），两者完全不在一个世界。同时 299/300 帖有反应但中位只有 15，**覆盖率高而绝对值低，正是真实读者随手点的形态**。

**这个号的增长完全靠"供给稳定"这一条。** 没有互推、没有外部矩阵、没有任何主动获客动作。ERR 9.99% 在本语料的资讯号里属于中上——说明内容本身站得住，但天花板也就在这里。

**三件套页脚是本报告里最值得记的一处"形式与实效背离"：** 频道 + 群 + 投稿 bot 是中文 TG 资讯号的标准配置，300/300 帖都在推，而实际结果是每 3.6 帖才有 1 条评论。**配置齐全不等于矩阵成立**——对照 [tginfo](tginfo.md) 同样的结构拿到 35,942 条评论，差别不在配置在内容形态：kejiqu 发的是改写过的第三方新闻，读者没有可讨论的对象，就像 [sspai](sspai.md) 只给标题和链接时一样。

## 十、法律风险

**风险等级：中。** 无刑事风险，核心问题集中在著作权与信息内容资质两项。

- **著作权：改写不等于免责（主要风险）。** 300 条内容全部来自第三方媒体，经 LLM 改写后发布。《著作权法》保护的是表达而非事实，**时事新闻（单纯事实消息）本身不受保护**（第 5 条第（二）项），但本案的内容多数不是"单纯事实消息"——它们包含记者组织的叙述、引述、数据编排与分析，属于受保护的作品。LLM 改写产生的是**演绎**而非独创，未经许可的改写与传播同时触及改编权与信息网络传播权。**减轻情节是它保留了来源标注（正文段尾注明站名）并在 12 条帖中给出原始链接**；加重情节是它对单一信源的依赖度高达 62%，构成系统性、持续性使用。责任主体为频道运营者。
- **配图的权属比正文更危险。** 298/300 帖配图，且正文是从信源页面抓取改写的，图片极可能同源。**新闻图片通常有独立著作权人（摄影师或图片社），不适用"时事新闻"例外，也不受"适当引用"保护**——引用文字可以说明问题，整张配图很难主张必要性。本语料里 [solidot](solidot.md) 的编译稿只用文字、不配图，规避的正是这一条。
- **《互联网新闻信息服务管理规定》的资质问题。** 该号持续转载时政、经济、科技类新闻信息并面向公众提供，在中国法下属于"互联网新闻信息服务"中的转载服务，需取得许可，且转载源须在国家网信部门公布的稿源单位名单内。**本案的运营主体与服务器位置不可观测**——若在境内则资质缺失明确；若在境外，则中国法无直接管辖，但内容面向中文用户仍可能触发访问层面的处置。**这是本报告最大的未验证变量。**
- **事实错误的责任。** 管道无人值守（第七节论证），LLM 改写引入事实错误的风险无人拦截。96 天样本里没有出现勘误，但这不能证明没有错误——只能证明没有人在纠错。**如果某条改写扭曲了对具体企业的负面表述，可构成商业诋毁（《反不正当竞争法》第 11 条）或名誉侵权。** 目前无实例，属潜在风险。
- **不适用**：不涉及开设赌场罪（300 条 0 条博彩内容、0 个博彩域名；"加拿大"3 次命中全部是新闻里的国名，与 `加拿大 PC28` 无关）；不涉及传播淫秽物品罪（0 条成人内容）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条导流；"代收""流水""上分""车位"各 1–3 次命中全部是技术与财经新闻的常规用词）；不涉及非法经营罪（0 收入、无支付业务）；不涉及广告法责任（0 条商业广告，23 条粗筛命中已逐条排除，见第五节）。

**责任主体**：频道运营者。样本中未暴露任何自然人身份——0 个第三方 @、0 个联系方式、投稿 bot 是唯一的对外接口。
