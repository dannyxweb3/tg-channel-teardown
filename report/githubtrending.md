> **频道 · 11,579 订阅 · 2.52 帖/天 · 成熟中位阅读 744 · ERR 6.43% · 存活率 100.0%**
> 数据来源：`scripts/tg_recon.py dump githubtrending --limit 300` → [data/recon/githubtrending.jsonl](../data/recon/githubtrending.jsonl)
> 抓取时间 2026-09-20 · 样本 300 条（2026-05-23 → 2026-09-20，跨度 119 天）

**一句话结论：300 条帖子、300 条链接、一个域名、id 跨度恰好 300、存活率 100.0%——又一个纯机器流。但它与本语料此前的机器流样本有一个实质差别：它有一套真正在工作的标签体系，而那套标签的分布本身就是一份 2026 年开源生态的切片——三分之一的帖子标了同一门脚本语言，四分之一标了同一门带类型的前端语言，而有 30 条（10%）标的是同一个 AI 编码工具的名字。一个纯粹的抓取脚本，因为顺手把语言与话题标签搬了过来，意外变成了一个可以统计的观测装置。**

## 二、核心发现一：一个机器流意外成了观测装置

**标签的分布：**

| 类别 | 标签 | 次数 | 占比 |
|---|---|--:|--:|
| **语言** | 某脚本语言 | **100** | **33.3%** |
| | 某带类型的前端语言 | **80** | 26.7% |
| | 某系统语言 | 40 | 13.3% |
| **话题** | 人工智能（泛） | 41 | 13.7% |
| | **某 AI 编码工具** | **30** | **10.0%** |
| | 大模型 | 29 | 9.7% |
| | 某模型上下文协议 | 24 | 8.0% |
| | AI 智能体 | 23 | 7.7% |

**这些标签不是运营者设计的，是从上游仓库的语言字段与话题字段直接搬过来的。**

**但搬过来这个动作使它们变成了可统计的：**

> **一个抓取"当下最热门的开源项目"的脚本，在 119 天里为每条内容留下了语言与话题的标记。**
> **把这 300 条的标签汇总起来，得到的是这段时间里开源热度分布的一个切片。**

**本语料此前的机器流样本**（[zhihuribao_rss](zhihuribao_rss.md)、[shuangyunews_rss](shuangyunews_rss.md)、[stopCA](stopCA.md)、[wublock](wublock.md)、[newmobilelife](newmobilelife.md)）**全部是零标签或几乎不用标签。**

**这是第一个带完整标签体系的机器流，而它的标签恰好是可聚合的。**

**本语料由此得到一条：**

> **当一个自动流搬运的是结构化的上游元数据时，它的标签分布会成为一份关于上游的统计。**
> **运营者没有这个意图，但数据有这个属性。**

**其中最值得单独记的是那 30 条（10%）标着某个 AI 编码工具名字的帖子。**

**本语料在 [sharecentre](sharecentre.md)、[what_youread](what_youread.md)、[lover_links](lover_links.md) 三个样本里观察过 2026 年中文 AI 工具生态的需求侧**（API 中转、模型访问、工具推荐）。

**这是第一次从供给侧看到同一件事：围绕某一个工具，有足够多的开源项目在短期内进入热门榜。**

**本报告不对这个数字作进一步推断**——**"热门榜"的排序机制本身不可知，而 300 条是一个小样本。**

**但它作为一个可观测的事实值得记录。**

## 三、核心发现二：又一个"三满分"机器流

**id 跨度恰好等于可见条数（300 = 300）、存活率 100.0%、域名 100% 单一。**

**本语料的"三满分"样本至此四个：**

| 样本 | 存活率 | 单一域名占比 | 频率 |
|---|--:|--:|--:|
| [stopCA](stopCA.md) | 100.0% | **零域名** | 恰好 1.00/天 |
| [zhihuribao_rss](zhihuribao_rss.md) | 100.0% | 每条三个固定域名 | 4.11/天 |
| [newmobilelife](newmobilelife.md) | 100.0% | **100%** | 25.00/天 |
| **githubtrending** | **100.0%** | **100%** | **2.52/天** |

**四个样本的频率跨越 25 倍，而它们的存活率都是满分。**

**本语料在 [lychee_wood](lychee_wood.md) 第六节确立过"删除率的决定因素是内容有没有一个过期时刻"，并在 [xuehuashe](xuehuashe.md) 第三节补上"× 运营者是否选择就地替换"。**

**这四个样本给那条规律补上一个更简单的判据：**

> **没有人在维护的流，不会有删除。**
> **删除是一个人工动作，而一个纯定时任务不会执行它。**

**这条判据与"内容有没有过期时刻"并不冲突，而是更底层：**

> **先问有没有人在管，再问管的人要不要删。**

**ERR 6.43% 落在本语料的"机器聚合"档**（3–10%，[stopCA](stopCA.md) 第三节确立的分类框架）。

**而它与 [stopCA](stopCA.md)（68.25%）的差别正是那一节的核心结论：**

> **ERR ≈ f(内容的不可替代性)。**

**"当下热门的开源项目"这件事，任何人都可以从上游直接看到**——**可替代性极高，所以 ERR 落在最低档。**

**转发均值 9.6 却不低**（高于 [zhihuribao_rss](zhihuribao_rss.md) 的 3.8、[newmobilelife](newmobilelife.md) 的 1.8）。

**原因在 [ksc666](ksc666.md) 第二节的"产物的适用面"：一个具体的开源项目，对看到它的人有明确的可用性，而一条新闻摘要没有。**

## 四、核心发现三：URL 抽取误判的第二种成因

**域名统计中出现两个不是域名的条目：一个形如 `<文件名>.md`（3 次），一个形如 `<应用名>.localhost`（1 次）。**

**本语料在本批 [rsshub](rsshub.md) 第四节刚记录过一次 URL 抽取的误判，成因是"正文里的中文句子包含域名形态的字符串，Telegram 的自动识别把整句话的一部分标成了链接实体"。**

**这个样本的误判成因不同：**

> **被搬运的项目说明文档里包含文件路径与本地开发地址，而它们在形态上与域名相同。**

**两种成因的共同点是：Telegram 的自动链接识别不区分"这是一个可访问的域名"与"这是一个碰巧长得像域名的字符串"。**

**本语料由此把这条方法论限制补完整：**

| 误判成因 | 形态 | 样本 |
|---|---|---|
| 正文中的域名形态字符串被连带识别 | 一整句话被记成域名 | [rsshub](rsshub.md) |
| **技术文档中的文件路径与本地地址** | **`*.md`、`*.localhost` 一类** | **githubtrending** |

**两者在全语料的合计占比已在 [rsshub](rsshub.md) 第四节量化（0.594% 的 URL 记录），而本样本的两个条目（合计 4 次）正落在那个量级里。**

**对本报告的影响为零：** **代码托管域名出现 300 次，那两个条目分别是 3 次与 1 次，不影响"100% 单一域名"这一论断的实质**（准确表述应为：300 条帖子的目标链接全部指向同一个代码托管平台，另有 4 次来自被搬运文档内部的路径字符串）。

## 五、其余维度

**实现技术思路：抓取 → 模板拼接 → 定时推送。**

| 层 | 做法 |
|---|---|
| 内容 | **标签行 + 项目描述**（正文中位 507 字） |
| 链接 | **每条一个仓库地址** |
| 标签 | **上游的语言与话题字段直接搬运** |
| 互动 | 反应开放（157 帖），评论未开放 |
| 自动化 | **完全** |

**正文中位 507 字、max 919——比本语料的其他机器流长得多**（[zhihuribao_rss](zhihuribao_rss.md) 48 字、[newmobilelife](newmobilelife.md) 111 字、[stopCA](stopCA.md) 172 字）。

**原因是它搬的是项目描述，而那是一段现成的英文说明。**

**按 [newmobilelife](newmobilelife.md) 第三节确立的机器模板两型，它属于"拼接型"：字段拼接，字段内容自由但总长被截断（max 919）。**

**成本（月）：¥0–100。** 一个定时抓取脚本；零域名、零存储、零 bot。

**与本语料的 RSS 矩阵样本**（[zhihuribao_rss](zhihuribao_rss.md) 第七节估整个矩阵 ¥30–200/月）**同一量级。**

**收益：¥0。** 粗筛 0/300、零收款账号、零联盟参数、零推广码、零广告、零站外商业链接。

**属"不变现十五种类型"中的"没有变现"一类。**

**未变现的承载力：¥300–2,000/月。** **受众是关注开源动态的开发者，质量高；但 ERR 6.43% 意味着单帖实际触达仅 744 人，而 2.52 帖/天的版面也有限。**

**增长：无主动机制。** 零互推（`t.me` 0 次）、零买量；**频道名是"代码托管平台名 + 热门"的直译组合，属"信源名占位"一类**（与 [zhihuribao_rss](zhihuribao_rss.md) 同组）。

**转发均值 9.6 是它唯一的外溢通道。**

## 六、法律风险

**风险等级：低。**

- **内容：公开代码仓库的标题、描述与链接。** 300 条全部指向同一个代码托管平台的公开项目页。
- **著作权：接触面极小。** **项目描述是仓库作者公开发布的元数据，其传播符合开源社区的惯例与该平台的公开 API 用途；每条都带原仓库链接。** **这与本语料 [shuangyunews_rss](shuangyunews_rss.md)（绕过付费墙的全文镜像）不在同一范畴。**
- **平台 API 的使用条款。** 抓取热门榜通常通过该平台的公开接口或页面进行。**若通过接口，需遵守其速率与用途限制；若通过页面抓取，则可能违反其服务条款。** **两者都属合同层面，且 2.52 帖/天的量级极小。**
- **零商业行为。** 零广告、零收款、零联盟参数——**切断所有以营利为要件的路径，也排除了《广告法》第 14 条的适用场景。**
- **零数据处理。** 无 bot、无评论区、无表单。
- **境内连接点：无。** 内容为英语、指向国际代码托管平台、频道名为英文。**中国法无直接管辖意义。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（0 条成人内容、0 个文件）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个支付通道、0 条商业导流）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（无 bot、无数据收集）；不涉及提供翻墙服务（唯一的域名是代码托管平台）。

**责任主体**：运营者（单账号，**身份在样本中不可见**）。**暴露面：零自有域名、零收款、零商业关系——一个只搬运公开元数据、不删除、不变现、不互推的自动流，几乎没有可被追究的接口。**
