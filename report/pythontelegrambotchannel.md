## 二、核心发现一：997 个链接，每条帖 6.3 个

**代码托管平台链接 997 条，分布在 159 条帖里——平均每条 6.3 个。**

**这个密度在本语料是第二高的**（第一是 [hao123f](hao123f.md) 的每条 8 个 `t.me`，但那是索引群）。**在频道类里，它是第一。**

**结构从正文能直接读出来：** 发版公告的格式是「我们刚发布了 vX.Y.Z，感谢所有贡献者」，**后面逐条列出这一版合并的每个 PR，每条一个链接。** 最长的一条 4,049 字——**那是一个大版本的完整变更清单。**

**标签也是 PR 编号**（`#1012`、`#963`、`#806`、`#1019`、`#1076`、`#1631`、`#1744` 等），**这使频道内搜索可以按 PR 号直接定位到它是在哪一版进的。**

**本语料的"发布频道"至此四个，做法差别很大：**

| 频道 | 发版公告的内容 | 可回溯性 |
|---|---|---|
| [surfboardnews](surfboardnews.md) | 变更说明 + 同名 APK 附件 | **差**（192 个同名文件，无版本号） |
| [XPlus_Channel](XPlus_Channel.md) | 转述上游 changelog | 中 |
| [ACL4SSR](ACL4SSR.md) | 更新项清单（无链接） | 中 |
| **pythontelegrambotchannel** | **逐 PR 列出 + 逐条链接 + PR 号标签** | **完整** |

**这是唯一一个"看频道就能完整回溯项目历史"的样本。**

**而它的存活率 95.8% 保证了这份档案的完整性**——**对照 [ACL4SSR](ACL4SSR.md) 的 10.2%（删旧更新日志）、[Hao12News](Hao12News.md) 的 93.6%（删过时教程）：那两个号删的是"已经没用的信息"，而版本历史永远有用。**

**本语料的删除动因分类至此可以补一条：内容是否有历史价值，决定了删除率。** 教程、线报、广告物料会过期；**版本记录、档案、判断记录不会。**

## 三、核心发现二：ERR 67.23% 与 0.04 条/天

**十一年 159 条，平均 24 天一条，而 ERR 67.23%——每 1.5 个订阅者就有 1 个看过。**

**这是"查着用"阅读模式的第三个样本**（前两个是 [QuanX_API](QuanX_API.md) 81.51%、[ACL4SSR](ACL4SSR.md) 166.00%）。

**三者的共同点非常一致：**

|---|--:|--:|---|
| [ACL4SSR](ACL4SSR.md) | 0.02 | 166.00% | 规则集更新 |

**三个号都是开发者工具的发布口、都是极低频、ERR 都在 67%–166%。**

**本语料由此可以把这条关系写成一个可用的判断：开发者工具类频道的 ERR 通常是内容类频道的三到十倍，而它的频率通常低一到两个数量级。** 原因是同一个：**这类内容不是"读完就过去了"，而是"需要时回来查"。**

**反应中位 64、最高 365** 在一个只有 1.75 万订阅的号上相当高。**结合评论 1,328 条（覆盖 47%），这是一个真实活跃的开发者社区。**

**评论的性质与 [ACL4SSR](ACL4SSR.md)、[QuanX_API](QuanX_API.md) 不同。** 那两个的评论是故障报告（"我这里不工作"），**而这个号的评论覆盖率更低（47% vs 78% / 55%）、单帖上限更低（76 vs 249 / 392）**——**说明它的评论更接近"讨论"而不是"求助"。**

**合理解释：一个 Python 库的用户是开发者，遇到问题会去提 issue 而不是在 Telegram 评论区喊。** **而代理工具的用户是普通人，Telegram 评论区就是他们唯一的求助渠道。**

## 五、实现技术思路

**极简：一个频道 + 一个配套讨论群（被引用 3 次）。零 bot、零域名、零文件托管（0 个附件）。**

**发版公告大概率是半自动的**——**逐 PR 列出、每个 PR 一个链接、标签是 PR 号，这些都可以从版本控制系统的发布说明自动生成。** 但**无 cron 指纹、间隔极不规则（0.04 条/天），说明触发是人工的**（发版时手动发一条）。

**存活率 95.8%，删掉的 7 条大概率是发错或重复。**

## 九、法律风险

**风险等级：低。** 本语料合规状况最好的样本之一。

- **内容：开源项目的发版记录。** 无任何法域下的敏感内容。
- **著作权：自有项目。** 997 个链接全部指向项目自己的仓库。
- **广告与消费者保护：不适用。** 十一年零商业内容、零荐证、零收款。
- **开源许可：合规无疑。** 一个把每个 PR 都公开列出、仓库公开、文档公开的项目，**源码可得性与贡献可追溯性都是最高水平。** 对照 [XPlus_Channel](XPlus_Channel.md) 第九节（89 条消息无一提到源码仓库，而它分发基于 GPLv2 上游的二进制）——**两者处在开源合规谱系的两端。**
- **评论区责任：1,328 条技术讨论，风险极低。**
- **管辖：内容为英文、项目为国际开源社区，无中国落地连接点。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（0 条成人内容）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（无个人信息处理）；**不涉及《计算机信息网络国际联网管理暂行规定》——与本语料的代理生态样本不同，一个 Telegram bot 开发库与网络管控规避无关。**

**责任主体**：开源项目的维护团队（公开）。**暴露面：全部公开，且这是开源项目的常态与要求。** **本语料的匿名样本（[projectXtls](projectXtls.md)、[moeisland](moeisland.md)）与这个号的差别不在技术，在业务性质——不做灰色业务就不需要匿名。**
