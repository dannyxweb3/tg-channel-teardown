## 二、核心发现一：`xhq` 这三个字母

**本轮的 [vps_xhq](vps_xhq.md) 在样本内 2 次引用了 `xhqcankao`。**

**两者的用户名都带 `xhq`：**

```
vps_xhq     显示名「VPS 信号旗播报」      xhq = 信号旗
xhqcankao   显示名「风向旗参考快讯」      xhq = 信号旗 + cankao = 参考
```

**`xhqcankao` 的显示名是「风向旗」，但用户名里写的是「信号旗」。**

**这是一次改名留下的痕迹。**

**Telegram 的用户名一旦更改，所有旧链接全部失效**——**一个 16 万订阅的频道换掉用户名，等于放弃历史上所有被转发过的链接。** 所以**改显示名容易，改用户名几乎不可能。**

**这使用户名成为判断账号血缘最可靠的字段：显示名可以随时重塑品牌，用户名会一直留着最初的那个名字。**

**本轮此前的矩阵识别全部依赖页脚链接密度**（[在花](TestFlightCN.md)、[1024](inside1024.md)、[喵](appmew.md)、[LIHAI](lihaiba.md)、[TG*库](fufeikc.md)）。**这一次是第一次靠用户名的拼音残留确认。**

## 三、核心发现二：每半小时一次的调度

**分钟按 30 取模：**

```
mod30 = 1   47 条
mod30 = 0   39
mod30 = 4   36
mod30 = 3   31
mod30 = 2   27
────────────────────
mod30 ∈ {0,1,2,3,4} 合计 180 条（60%）
```

**也就是说，60% 的消息落在 `:00–:04` 或 `:30–:34` 这两个五分钟窗口里。**

**按 5 取模则几乎平均**（78 / 60 / 59 / 55 / 48）——**排除了 `*/5` 的可能。**

**间隔中位 1,875 秒 = 31.25 分钟，与 30 分钟周期吻合。**

**而 `<60 秒` 与 `<10 秒` 都是 0%** ——**它从不在同一分钟里发两条。** **这是本轮唯一一个同时做到"有明确调度周期"和"零连发"的样本。**

**含义是：调度器每半小时唤醒一次，把队列里的稿子在随后几分钟内逐条发出，且刻意留出间隔。**

**这条留出间隔的规则是人为设计的**——**技术上连发更省事，隔开发是为了让每条稿子在时间线上各占一格。**

**本轮的 cron 粒度梯度现在有五级：**

| 频道 | 周期 | 签名 |
|---|---|---|
| [programmerjokes](programmerjokes.md) | **每天** | 分 `:30` 98% + 秒 `:05` |
| [sspai](sspai.md) | **每小时** | 分 `:20` 100% |
| **xhqcankao** | **每半小时** | **mod30 ∈ {0..4} 占 60%** |
| [solidot](solidot.md) | **每 5 分钟** | 分 mod 5 = 0 占 92% |
| [theblockbeats](theblockbeats.md) | **每分钟** | 秒 `:02` 占 86% |

**五级周期对应五级时效性：梗图 → 站点新稿 → 科技财经快讯 → 科技短讯 → 加密行情。**

**小时分布进一步说明它不是全天候**：6–21 点每小时 11–24 条，**22 点到次日 5 点几乎为零（合计 10 条）。** **调度器只在白天运行。**

> **彭博与华尔街日报均设有付费墙且维权积极** ——**这是本案著作权风险高于 tnews365 的主要原因。**
