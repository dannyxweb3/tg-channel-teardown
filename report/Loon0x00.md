## 二、核心发现一：它是一个 iOS 代理客户端的技术支持群

**关键词分布直接给出了主题：**

```
配置 31 | /sb 27 | 规则 14 | 插件 10 | 代理 10 | 更新 10 | 节点 7 | 去广告 5 | 机场 3 | TF 2 | 证书 1 | 分流 1
```

**Loon 是 iOS 平台的一款代理/规则分流客户端**（与 Shadowrocket、Quantumult X、Surge 同类）。**它不是"机场"（不提供节点服务），是一个装节点用的工具。** 这个区分在法律定性上很关键（见 §八）。

**样本内唯一的外链之一直接印证了这一点：**

> `cdn.jsdelivr.net/gh/blackmatrix7/ios_rule_script@master/rule/Shadowrocket/ChinaMax/ChinaMax_Domain.list`

**这是一个公开的 GitHub 分流规则仓库**——中文 iOS 代理工具生态里最常被引用的规则集之一。

**7 条超过 60 字的消息构成了这个群的全部信息量：**

> **节点问题，对比测试结果**：1：A 机场香港节点突然不能加载字幕，改为日本节点正常　2：日本节点 1 失效，更改为日本 3 恢复正常　3：换另一家机场正常

**这五条分别是：故障对比排查、多设备配置同步方案、路由器与客户端冲突诊断、TestFlight 加入流程、一个与代理无关的 iOS 系统问题。**

**它们的质量不低——第一条是有对照组的排查（换节点、换机场、逐项排除），第二条是一个真正可用的工程方案（用 GitHub 仓库做配置源，只在本地保留节点与证书）。**

**这是大型技术支持群的典型信噪比：真正有价值的问答被淹没在闲聊里，而 508 条/天的速度让任何有用的回答在几分钟内就滚出屏幕。**

## 三、核心发现二：公开封禁日志，连用户 ID 一起公示

**样本内出现 27 次 `/sb@KinhRoBot` 指令，以及一条完整的封禁日志：**

> 🧧手机【某昵称】📸 **已永久封禁并上报数据** `#KinhRoBotLog` `#SB` `#OperateID456176417` `#UserID5802660511`

**（本报告不复现被封账号的昵称。）**

**这条日志的信息量很大：**

| 元素 | 含义 |
|---|---|
| `/sb` 指令被打了 27 次 | **半天里至少 27 次封禁操作** |
| 「已永久封禁**并上报数据**」 | **不只是本群封禁，还上报给了某个共享黑名单** |
| `#OperateID` | 执行封禁的管理员 ID |
| `#UserID` | **被封用户的数字 ID，公开写在标签里** |
| `#KinhRoBotLog` | 日志被打上统一标签，可检索 |

**"上报数据"这个措辞指向跨群共享的反垃圾体系** ——与本轮 EmbyPublic 使用的 CAS（Combot Anti-Spam）是同一类机制，**但 Loon0x00 的实现更进一步：它把操作者与被封者的 ID 都公示出来。**

**这个做法有清晰的两面性：**

**好的一面**：可追溯、可复核、对投放者形成威慑。半天 27 次封禁说明群面临持续的广告轰炸，**这套机制是它能在 508 条/天的洪流里保持可用的原因。**

**成问题的一面**：**把被封用户的 Telegram 数字 ID 公开写进标签，是在公开传播账号标识信息。** 数字 ID 虽不直接等于个人身份，但它是跨群关联同一账号的可靠键——**在中国大陆《个人信息保护法》的口径下，这属于可识别自然人的网络身份标识（见 §八）。**

**44.5% 的 id 缺口（541 → 300）与这套封禁机制吻合**：半天删掉 241 条，大部分应是被清理的广告。

## 八、法律风险

> **level: medium。**
>
> **1｜代理客户端与"机场"的法律区分（本案最需要厘清的一点）。** Loon 是一个**规则分流客户端**，本身不提供网络出口服务——**它相当于一个浏览器，而不是一个网络运营商。** 中国大陆《计算机信息网络国际联网管理暂行规定》第六条禁止的是"自行建立或使用其他信道进行国际联网"，**指向的是提供信道的一方（即"机场"），而非工具的开发者或使用者社区。**
>
> **本群不销售节点、不提供订阅、不推广任何机场**——样本内「机场」仅出现 3 次且全部是用户在描述自己遇到的故障（"A 机场香港节点突然不能加载字幕"）。**外链仅 2 个，一个是公开的 GitHub 分流规则集，一个是社交媒体链接，均无落地页、无收款、无 aff 参数。**
>
> **因此它与本轮的 feiyu123、gitbig、blacktechsharing、Lottery_home 有本质区别**：那四个是**为机场提供有偿推广渠道**，本群是**工具的用户支持社区**。**这是把等级定在 medium 而非 high 的核心理由。**
>
> **残余风险在于**：讨论如何配置代理工具，在监管口径上仍处于灰色地带；且群内用户的实际用途（连接境外节点）不受群方控制。
>
> **2｜公开被封用户的 Telegram 数字 ID。** bot 的封禁日志把 `#UserID` 与 `#OperateID` 写进标签公开发布。中国大陆《个人信息保护法》第四条将"网络身份标识信息"列为个人信息；第十条禁止非法收集、使用、加工、传输他人个人信息。**Telegram 数字 ID 是跨群关联同一账号的可靠键，公示它构成对个人信息的公开传播。**
>
> **减轻情节**：目的正当（反垃圾）、数据来源于群内公开行为、不涉及真实姓名或联系方式。**加重情节**：「已永久封禁**并上报数据**」表明存在跨群的数据共享，**这已超出单群自治的范围。** 责任主体为群主与 bot 运营者。**量级不重，但这是本群最实在的一处合规瑕疵。**
>
> **3｜TestFlight 相关内容。** 样本内有一条介绍如何申请加入开发者 TestFlight 的说明。**这是 Apple 官方提供的测试分发渠道，完全合规，不构成任何问题。** 列此是为了避免把"TF"误读为灰产黑话。
>
> **不适用的四条**：不涉及侵犯著作权罪（0 个资源链接、0 个网盘、3 个文件共 0.00 GB，且无破解软件）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 条博彩/诈骗导流，且主动封禁广告 27 次）；不涉及非法经营罪（零收入、无经营行为）；不涉及传播淫秽物品罪（0 条成人内容）。
>
> **观测限制声明**：本报告基于 0.6 天、300 条平均 6 个字的样本，**是本轮跨度最短的一份**。判断建立在关键词分布、bot 日志格式与 7 条长消息之上，**置信度为 medium。**
