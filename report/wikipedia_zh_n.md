# wikipedia_zh_n · wikipedia-zh

> **群 · 22,752 成员 · 可见 300 条 · 发言人 20 · bot 消息 40% · 100 条/天 · 存活率 94.9%**
> 数据来源：`scripts/tg_recon.py dump wikipedia_zh_n --limit 300` → [data/recon/wikipedia_zh_n.jsonl](../data/recon/wikipedia_zh_n.jsonl)
> 抓取时间 2026-09-20（含发言人字段的重抓） · 样本 300 条（2026-09-17 → 2026-09-20，跨度 3 天）

**一句话结论：40% 的消息来自 bot，而这些 bot 干的不是发广告或做群管——它们在把一个百科项目的站内事件同步过来。最高频的一个是验证码 bot（89 条），另有两个把站内的公告栏与管理操作日志中继进群（「警告成功。該用戶現在共有…」「[I - wm-bot]」这种 IRC 中继前缀）。20 个发言人、top10 占 91%，2.28 万成员里说话的是二十个人。这是本语料第一个"把一个外部协作项目的运维事件流搬进 Telegram"的样本，形态上最接近 [M_Team_Chat](M_Team_Chat.md) 的站内数据播报，但那个播报的是虚拟积分，这个播报的是内容治理动作。**

## 二、核心发现一：bot 中继的是内容治理动作

**119 条 bot 消息来自五个 bot，功能可分三类：**

| bot | 条数 | 功能 |
|---|--:|---|
| 某验证码 bot | **89** | **入群人机验证** |
| 某站内中继 bot | 23 | 把百科的公告栏同步进群 |
| 某机器人管理助手 | 20 | IRC 中继（消息带 `[I - wm-bot]` 这类前缀） |

**第三类值得单独说：`[I - wm-bot]`、`[D - Internet…]` 这种前缀是 IRC 频道消息中继的标准格式。** **说明这个群与一个 IRC 频道是打通的**——**百科项目的技术社区长期使用 IRC，而这个 bot 把 IRC 的事件流桥接到了 Telegram。**

**能看到的事件内容包括站内公告栏的更新、以及管理操作的结果（「警告成功。該用戶現在共有…」）。**

**本语料此前记录过三种 bot 用途**（见 [M_Team_Chat](M_Team_Chat.md) 第三节）：播报站外数据、群管理、关键词服务。**这里是第四种：跨协议中继。**

**它与 [M_Team_Chat](M_Team_Chat.md) 的播报有一个本质差别：**

| | [M_Team_Chat](M_Team_Chat.md) | **wikipedia_zh_n** |
|---|---|---|
| 播报什么 | 站内虚拟积分的众筹进度 | **站内的内容治理动作** |
| 目的 | **激励**（制造共同目标） | **协同**（让编者知道发生了什么） |
| 受众 | 全体成员 | **少数活跃编者** |

**而这解释了它的发言结构：20 个发言人、top10 占 91%。** **一个 2.28 万成员的群，实际参与的是二十个人——因为真正需要看这些运维事件的就是这二十个人。**

## 三、核心发现二：89 条验证码，以及 94.9% 的存活率

**最高频的 bot 是验证码 bot，89 条（占 bot 消息的 75%、占全部消息的 30%）。**

**三天 89 次入群验证**——**平均每天约 30 人尝试进群。**

**而存活率 94.9%（316 个 id 存 300）在本批十一个群里排第二**（仅次于 [PublicTestGroup](PublicTestGroup.md) 的 85.71%……实际上本群更高）。

**把这两个数字放在一起，得到本语料"群治理"的第六种机制：**

| 机制 | 过滤对象 | 成本 | 样本 | 存活率 |
|---|---|--:|---|--:|
| 对话速度 | 垃圾投放没有曝光价值 | 0 | [PublicTestGroup](PublicTestGroup.md) | 85.71% |
| 话题门槛 | 看不懂的人 | 0 | [BotTalk](BotTalk.md)、[v2rayN](v2rayN.md) | 40%–41% |
| 站外身份绑定 | 没有站内账号的人 | ≈0 | [M_Team_Chat](M_Team_Chat.md) | 26.48% |
| 字体过滤 | 特定地域的输入 | ≈0 | [GIFgroupTW](GIFgroupTW.md) | 2.26% |
| 隐藏历史 | 潜在搬运者 | 0 | [tgzhcn](tgzhcn.md) | — |
| **入群验证码** | **自动化脚本** | **≈0** | **wikipedia_zh_n** | **94.9%** |

**验证码是这六种里最直接的一种：它在门口就把机器人挡住了。**

**结果也是最好的：94.9% 的存活率意味着几乎没有消息需要被删除——垃圾根本没进来。**

**对照本批的中文城市群：[beijingz](beijingz.md) 无任何门槛、存活率 0.10%；[jinan_tg](jinan_tg.md) 有 4 个管理 bot 在事后删、存活率 2.77%。** **而这个群用一个验证码 bot 做事前拦截，存活率 94.9%。**

**本语料由此得到一条明确的判断：事前拦截的效率比事后清理高两个数量级，而成本更低。**

## 四、核心发现三：20 个发言人撑起 2.28 万成员

**发言人 20、top10 占 91%**——**本语料集中度第二高的群**（第一是 [hao123f](hao123f.md) 的 18 人 / 97%，但那个是 bot 刷屏）。

**去掉 5 个 bot，人类发言者约 15 人。**

**这与 [nexitallyusers](nexitallyusers.md)（24 人 / 84%，群已空）形态相似但性质相反——本语料在 [PublicTestGroup](PublicTestGroup.md) 第四节确立过区分方法：看"可见/天"。**

| | [nexitallyusers](nexitallyusers.md) | **wikipedia_zh_n** |
|---|--:|--:|
| 发言人 | 24 | 20 |
| top10 占比 | 84% | 91% |
| **可见/天** | **0.1** | **100** |
| 判读 | 空壳 | **小而活跃的工作群** |

**100 条/天、20 个发言人——人均每天 5 条。** **这是一个真正在运转的协作群，只是参与者少。**

**内容形态印证这一点**：正文中位 24 字、最长 223 字，**全是短促的工作交流**；域名只有百科主站 14 条与基金会站 2 条，**几乎没有外部链接。**

**标签 `#warn` 3 次**（对应管理操作中继里的警告事件）、`#wikipedia` 2 次。

**2.28 万成员里绝大多数是围观者**——**这在一个知名项目的公开群里是常态：人们加进来是为了"在场"，不是为了参与。** 与本语料 [tgzhcn](tgzhcn.md)（3.85 万成员、在线率 0.97%）的"沉淀型社区"是同一形态。

## 五、实现技术思路

**极简，且全部依赖外部生态：**

```
百科站内事件（公告栏、管理操作）
        ↓  中继 bot
IRC 频道
        ↓  桥接 bot（带 [I - wm-bot] 前缀）
Telegram 群
        ↑  验证码 bot 守门
```

**零自建基础设施：没有域名、没有服务器、没有自有 bot**（五个 bot 从命名看都是社区通用工具或项目自有工具）。

**"IRC → Telegram 桥接"是这个群最特别的技术选择。** 它说明**这个社区的主阵地不在 Telegram**——**Telegram 只是一个镜像端。**

**本语料的"频道/群是镜像"至此四种：**

| 源 | 镜像端做什么 | 样本 |
|---|---|---|
| 自有媒体站 | 分发 | [sspai](sspai.md) |
| 英文技术论坛 | 筛选 + 改链 | [hacker_news_feed](hacker_news_feed.md) |
| 中文羊毛论坛 | 原样镜像 | [zuanke8](zuanke8.md) |
| **IRC + 百科站内** | **跨协议桥接** | **wikipedia_zh_n** |

## 六、成本

**经常性（月）：¥0。**

| 项目 | 金额 |
|---|--:|
| 五个 bot | ¥0（社区通用工具或项目自有） |
| 管理人力 | ¥0–100（验证码自动拦截，几乎不需要人工） |
| 服务器 / 域名 | ¥0 |

**这是本语料成本为零的又一个样本，与 [PublicTestGroup](PublicTestGroup.md)、[BotTalk](BotTalk.md) 同档。**

**但它的"零成本"有一个前提：它依附于一个已经存在的、有自己基础设施的开源协作项目。** **中继 bot、IRC 频道、站内公告栏都不是这个群建的。**

**这与 [M_Team_Chat](M_Team_Chat.md)（依附于一个 PT 站）、[nexitallyusers](nexitallyusers.md)（依附于一个机场）是同一种结构：群是附属设施，成本在母体那边。**

## 七、收益

**¥0，且结构上不可能变现。**

**300 条消息：0 条广告、0 个联盟参数、0 个收款账号、0 个商业域名。** 域名只有百科主站与基金会站。

**这个群不存在变现的可能，原因有三：**

1. **它是一个非营利项目的社区** —— 在这样的群里卖广告会立刻引发社区反弹。
2. **20 个发言人的工作群没有广告价值** —— 2.28 万成员里活跃的只有二十个。
3. **内容是运维事件流** —— 没有任何可以插入广告的版面。

**未变现的潜在价值：本报告不给数字。** 与本语料其他"不能变现"的样本（[douban_read](douban_read.md) 的存档公信力、[M_Team_Chat](M_Team_Chat.md) 的非官方身份）相比，**这个是最彻底的——前两者至少在理论上有置顶位可卖，这个连版面都没有。**

| **项目名占位** | 群名是项目名 | **唯一机制** |
| 验证码守门 | 89 条/3 天 | **保证群不烂** |
| IRC 桥接 | `[I - wm-bot]` 前缀 | 与主阵地打通 |
| 互推 | 1 条 `t.me`（自指） | 无 |
| 买粉 | **无从判断** | |

**2.28 万成员来自项目名本身。** 本语料"关键词占位"的第九种形态：**项目名占位**——**与 [BotTalk](BotTalk.md) 的技术主题占位相邻，但更强：主题词可以被多个群共用，项目名只有一个正主。**

**它没有做任何增长动作，也不需要。** **而验证码 bot 保证了增长来的人不会毁掉这个群——这是本语料第一次看到"增长机制与治理机制是同一个东西"：门开着，但门口有人查。**

## 九、法律风险

**风险等级：低。**

- **内容：开源协作项目的运维事件流与编者交流。** 无任何法域下的敏感内容。
- **群主的管理义务：履行充分。** 验证码 bot 事前拦截、94.9% 的存活率、幸存内容完全干净——**这是本语料"已尽管理义务"证据最强的一个样本**（对照 [gouwu](gouwu.md)：幸存内容里挂着黑产广告，证明清理没发生）。
- **中继站内治理动作的隐私问题。** 管理操作日志会包含被警告用户的账号名（「該用戶現在共有…」）。**这些是百科站内已公开的管理记录**，**转发公开记录通常不构成《个人信息保护法》意义上的违法处理**；**但把它中继到一个 2.28 万成员的群里，扩大了传播范围**——**与本语料 [douban_read](douban_read.md) 第九节记录的"跨平台搬运使公开信息进入新语境"是同一类问题，强度更低（这里是社区自治记录，不是个人隐私）。**
- **IRC 桥接的数据流转。** 消息经过 IRC 与桥接 bot 两层第三方。**这在合规上不构成问题**（内容本身是公开的），**但它意味着群消息经过了群主不控制的环节**——与本语料 [titan_pain](titan_pain.md) 第九节记录的"嵌入修复代理"是同一类观察。
- **管辖：内容为中文（繁简混用），但项目是国际非营利组织运营，服务器在境外。** **中国法的管辖连接点弱于本批的城市群样本。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；不涉及传播淫秽物品罪（0 条成人内容）；不涉及侵犯著作权罪（无内容分发；域名全部指向该项目自己的站点）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个联盟参数、0 条商业导流）；不涉及非法经营罪（零收入且结构上不可能变现）。

**责任主体**：群主与管理员（身份在样本中不可见）。**暴露面：零域名、零收款、零自有基础设施。** **本语料中暴露面最小的一档，与 [PublicTestGroup](PublicTestGroup.md)、[GIFgroupTW](GIFgroupTW.md) 并列。**
