> ⚠️ 本报告不复现任何作品标识、作者账号、图源链接与角色/作品名。

> **频道 · 11,550 订阅 · 0.43 帖/天 · 成熟中位阅读 1,600 · ERR 13.86% · 存活率 94.9%**
> 数据来源：`scripts/tg_recon.py dump moepic --limit 300` → [data/recon/moepic.jsonl](../data/recon/moepic.jsonl)
> 抓取时间 2026-09-21 · 样本 300 条（2024-08-26 → 2026-07-19，跨度 691 天）

**一句话结论：本语料至此有三个插画搬运样本，而这一个的元数据最完整：每条帖子都是 `title / author / tags / url` 四个字段，其中作者名被写成了标签——于是点一下就能看到这个频道里那个画师的全部作品。它同时是三个里唯一一个不发原图的：294 张全部是压缩预览，文件只有 5 个。最完整的著录配上最不完整的交付，这个组合在本语料里是唯一的，而它恰好说明著录与交付服务的是两件不同的事。**

## 二、核心发现一：作者名被写成标签

**每条帖子的正文是一个四字段结构：**

```
title: <作品标题>
author: #<作者名>
tags: #<来源站的标签> #<…>
url: <插画平台的作品页>
```

**`author` 字段的值是一个标签，不是纯文本。**

**这意味着：读者点一下作者名，就能在这个频道里看到该作者的全部被收录作品。**

**本语料的"标签十五用"**（[tdlibchat](tdlibchat.md) 第四节确立第十五种"自荐"）**在这里出现第十六种：作者索引标签。**

**把它放进"为谁服务"的分类：**

| 用途 | 为谁服务 |
|---|---|
| 分类 / 属性检索 / 栏目 / 同义多语 / 工单编号 / **作者索引** | **读者检索** |
| 品牌 / 修辞 / 卖点 | 读者感知 |
| 纠错 / 自评 / 运营通报 | 读者知情 |
| 自嘲式偏题 / 装饰 | 社交或无 |
| 命令快捷键 | 机器 |
| 自荐 | 发言者自己 |

**它属于"读者检索"一支，但与该支的其他用途有一个结构差别：**

> **其余检索标签的取值来自一个有限的封闭集合**（颜色、平台、省份运营商、协议名）。
> **作者索引标签的取值是开放的**——**每收录一个新作者就多一个标签。**

**这带来一个代价：标签空间会无限增长，而 Telegram 的标签检索是全文匹配的，没有目录页。**

**读者只有在已经看到某个作者的作品时，才能点进去看他的其他作品；他无法浏览"这个频道收录了哪些作者"。**

**本语料由此补一条：**

> **开放集合的索引标签只支持"从一条到更多条"，不支持"从零开始浏览"。**
> **它是一个横向跳转机制，不是一个目录。**

**其余标签的分布则是封闭集合的典型形态：前三名是同一个作品的三种写法（原名、缩写、英文名），合计 188 次；其后是角色名与属性词。**

**这实际上是本语料 [cool_scripts](cool_scripts.md) 第三节"同义多语堆叠"的又一个实例**——**那个样本是中文/英文两种写法，这个样本是日文全称/日文缩写/英文名三种。**

**两个样本的动机相同：让用不同语言搜索的人落到同一批内容上。**

## 三、核心发现二：最完整的著录，最不完整的交付

**本语料的插画搬运样本至此三个，它们的著录与交付恰好反向：**

| 样本 | 著录字段 | 覆盖率 | 原图交付 | 平均体积 |
|---|---|--:|---|--:|
| [ovov1234](ovov1234.md) | **url** | 146/149 | **149 个原图** | 2.8 MB |
| [pixivshare](pixivshare.md) | **title + url + 题材标签** | 136/300 | **139 个原图** | 3.6 MB |
| **moepic** | **title + author + 来源标签 + url** | **280/300** | **无**（294 张压缩预览） | — |

**著录最完整的那个，交付最弱。**

**本语料在 [pixivshare](pixivshare.md) 第六节确立过：**

> **对素材类内容，决定价值的不是获取步骤，是交付质量。**
> **一张压缩过的壁纸和一张原图，获取成本一样，可用性差很远。**

**这个样本的存在要求把那条限定一下：**

> **那条判断适用于"素材"**（读者要拿去用）。
> **而这个样本的定位不是素材，是索引**——**读者在这里发现作品与作者，然后去原站。**

**证据是每条帖子都带着完整的来源链路：某社交平台 148 次 + 某插画平台 130 次，两个来源都给。**

**300 条帖子对 278 个来源链接，接近每条都有；而短链域名 150 次是那个社交平台自己的链接缩短服务，与前者是同一批链接的两种形式。**

**本语料由此把插画分发这个品类拆成两型：**

| 型 | 定位 | 交付 | 著录 | 样本 |
|---|---|---|---|---|
| **素材型** | **读者拿去用** | **原图** | 够用即可 | [pixivshare](pixivshare.md)、[ovov1234](ovov1234.md) |
| **索引型** | **读者去发现** | **预览即可** | **必须完整** | **moepic** |

**这条区分也解释了评论密度的差异：**

| 样本 | 评论/帖 |
|---|--:|
| [pixivshare](pixivshare.md) | 0.47 |
| [ovov1234](ovov1234.md) | — |
| **moepic** | **0.04** |

**索引型内容不产生问题**——**没有什么可问的，链接就在那里。**

**本语料在 [ksc666](ksc666.md) 第三节确立的"评论密度 = f(正文留白, 内容引发的问题数)"在这里得到一个下限值：** **一个四字段结构化著录，留白为零、问题也为零。**

## 四、核心发现三：ERR 13.86% 与结构化的代价

**ERR 13.86%，在三个插画样本里居中**（[pixivshare](pixivshare.md) 43.08%、本样本 13.86%、[ovov1234](ovov1234.md) 11.97%）。

**而它的正文中位是 130 字，另两个是 15 字与 0 字。**

**本语料在 [steamsteam](steamsteam.md) 第三节确立过"正文长度决定读者的参与形式"，并在 [EqualLeaks](EqualLeaks.md) 第二节修正为"共同点不是长度，是说了事实但没下结论"。**

**这个样本提供了一个新的角度：**

> **结构化著录本身就是一种"把结论写满"。**
> **`title / author / tags / url` 四个字段把一条内容的全部可说之处都占满了，读者既不需要补充，也不需要提问。**

**反应中位只有 2、max 只有 10**——**是本语料反应强度最低的图片类样本之一**（对照 [EZwalls](EZwalls.md) 中位 61、[JISFW](JISFW.md) 59.5、[pixivshare](pixivshare.md) 6）。

**转发均值 9.9 却不低**，**说明内容本身是有传播价值的，只是不引发"就地表态"。**

**本语料由此得到一条：**

> **著录的完整度与参与度负相关。**
> **一条信息被说尽了，就没有人接话了。**

**这与本语料在 [sharecentre](sharecentre.md) 第五节（625 字长文、评论 0.06 条/帖）观察到的是同一现象的两种形态：**

**那个是"写得太长"，这个是"写得太全"。**

## 五、其余维度

**实现技术思路：结构化模板 + 双来源链接 + 无原图。**

**零自有域名、零 bot、零服务器；`t.me` 6 次全部指向贴纸包。**

**5 个文件中有 4 个 mp4，其中最大的一个的文件名形如 `<数字 id>_<序号> - <作者名>(<数字 id>).mp4`——这是某社交平台媒体下载工具的命名格式。**

**本语料的"文件名取证十三形"**（[pixelexperiencechat](pixelexperiencechat.md) 第四节确立第十三形）**在这里得到第十四形：社交平台媒体下载器的 `<推文 id>_<序号> - <作者>(<作者 id>)` 格式。**

**它与第四形（短视频下载器的标题转连字符）的区别是：那个保留标题，这个保留 id 与作者**——**前者面向人，后者面向归档。**

**这与第二节的"索引型"定位是一致的：这个账号在做的是归档，不是分享。**

**正文中位 130 字、max 276**——**极窄的分布，与本语料的模板型样本同型**（[stopCA](stopCA.md) 极差 9 字符、[newmobilelife](newmobilelife.md) 111–151 字符）。

**按 [newmobilelife](newmobilelife.md) 第三节确立的两型，它属于"拼接型"：字段拼接，字段内容自由但总长被截断。**

**成本（月）：¥0。** 零基础设施；不存原图意味着连存储都省了。

**收益：¥0。** 粗筛 0/300、零收款账号、零联盟参数、零推广码、零广告。

**属"不变现十五种类型"中的"不能变现"一类**（与 [pixivshare](pixivshare.md)、[ovov1234](ovov1234.md) 同组）。

**未变现的承载力：¥500–3,000/月。** **与 [ovov1234](ovov1234.md) 同档：1.16 万订阅、ERR 13.86%；参与度低（反应中位 2、评论 0.04 条/帖）压低了上锚。**

**增长：0.43 帖/天、转发均值 9.9。** 零互推、零买量迹象、零关键词占位（频道名是一个通用词）。

## 六、法律风险

**风险等级：中高。** 低于本语料的另两个插画样本。

- **未经许可传播他人美术作品（主要风险）。** 与 [pixivshare](pixivshare.md) 第七节、[ovov1234](ovov1234.md) 第六节的分析一致：**依《著作权法》第 10 条第 12 项，未经许可通过网络提供他人作品构成侵权。**
- **但这个样本的侵权程度明显较轻，三条理由：**
  1. **不提供原图。** 294 张全部是 Telegram 压缩后的预览。**本语料在 [pixivshare](pixivshare.md) 第七节指出过"提供原图比提供压缩预览的侵权程度明显更重——它替代了读者访问原站的全部理由"。** **这个样本没有替代原站。**
  2. **著录最完整。** `title / author / tags / url` 四字段，覆盖 280/300。**《著作权法》第 24 条要求"指明作者姓名、作品名称"**——**这个样本是本语料唯一一个把作者与标题都作为独立字段列出的。**
  3. **双来源链接。** 两个平台的链接都给，**读者有明确且便利的路径回到原作。**
- **零营利。** 零广告、零收款、零联盟参数——**《刑法》第 217 条的营利要件不成立。**
- **题材构成。** 样本的标签体系以特定游戏作品的角色为主，**另有若干指向角色属性与服装的分类词。** **本报告未逐张核验 294 张图片；从标签构成看，未发现指向露骨内容的分类词**——**这与本语料 [pixivshare](pixivshare.md)、[ovov1234](ovov1234.md) 的情形不同，那两个样本各自出现过需要专门评估的题材分类。** **本样本在这一项上是三个中最干净的。**
- **角色形象的商标与版权。** 标签中的作品名与角色名指向商业游戏 IP。**这些是二次创作（同人）作品，在中国法下属著作权与商标的灰色地带**——**非商业同人实践中权利人通常不追究，而本频道是第三手传播者。**
- **零数据处理。** 无 bot、无表单、无收款。
- **境内连接点。** 简体中文频道名、受众以中文用户为主；**但标签体系以日文为主，说明相当部分受众是跨语言的。** **两个来源平台在中国大陆均不可直接访问，而本频道不提供任何访问手段。**
- **不适用**：不涉及开设赌场罪（0 条博彩内容、0 个博彩域名）；**不涉及传播淫秽物品罪**（标签构成中未见露骨分类词，294 张图片未逐张核验）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 个支付通道、0 条商业导流）；不涉及非法经营罪（零收入）；不涉及侵犯公民个人信息罪（无 bot、无表单）；不涉及提供翻墙服务（域名中无机场、节点、订阅）。

**责任主体**：运营者（单账号，**身份在样本中不可见**）。**暴露面：零自有域名、零收款、零商业关系、零原图托管**——**在本语料的三个插画样本里暴露面最小，而这与它"索引而非素材"的定位是一致的：它没有囤任何东西。**
