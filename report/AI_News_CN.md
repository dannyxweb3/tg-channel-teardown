**这说明它的转载管线是"整条抓、整条发"，不做任何清洗。**

**后果很具体：它每天替 8 个上游频道免费打了 300 次广告。** 一个正常的聚合号会把上游页脚删掉、换成自己的；它没有。

## 三、内容与技术

**3.1 上游是 TG 频道 + 网站的混合**

12 个可辨识来源里，**至少 6 个本身就是 Telegram 频道**（AI Pulse、风向旗参考快讯、在花频道×2、Roller 社区、AI 新闻资讯），其余是网站（cnBeta、aibase、Bloomberg）和状态页（OpenAI status、Claude status）。

**它连 OpenAI 与 Anthropic 的服务状态页都接了**（8 + 3 次）——**这是一个纯 RSS/API 层面的接入，说明上游清单是配置出来的，不是人挑的。**

`telegra.ph` 60 次说明部分长文被转存到了 Telegraph（TG 自带的长文托管），这是 TG 生态里绕过 4,096 字上限的标准做法。

**3.2 去重失效**

首行重复统计：

```
「DeepSeek V4.1 Flash 上线 C…」   5 条
「Horizon Summary: 2026-09…」    4 条
「DeepSeek V4.1 Flash预计9月1…」  2 条
「DeepSeek-V4.1-Flash 登陆 S…」  2 条
「Midjourney 开始测试 V8.2 编辑模…」2 条
```

**同一条 DeepSeek 新闻在样本里出现了至少 9 次**（三种不同标题写法）。样本内还能看到同一则「OpenAI 收紧 ChatGPT 广告政策」的新闻，以 cnBeta 版和另一家改写版**两条并存**。

**它没有跨源去重。** 多接一个源就多一份重复——**这正是"每天 76 条"的来源，也是 ERR 只有 1.11% 的直接原因。**

**3.3 定时痕迹**

```
秒：:02 出现 72 次 | :01 69 次 | :03 33 次 → 三秒窗口 174/300（58%）
分钟：最高 :28 仅 13 次 → 无分钟栅格
间隔中位 531 秒，<60 秒占 30%，<10 秒占 28%
```

**秒集中在 `:01–:03` 而分钟均匀分布**，说明它不是 `*/5` 这种整点栅格，**而是一个持续轮询的守护进程：每轮拉取耗时 1–3 秒，拉到就发。**

`<10 秒` 占 28% 是成批发布——一轮抓到多条就连着倒出来。

**小时分布覆盖全天 24 小时**（0 点 16 条、3 点 8 条、9 点 33、14 点 32），**零人工干预。**

**3.4 正文形态**

- 纯文本 185、网页预览 63、图片 48、文件 4（4 个 mp4，0.01 GB）
- **正文中位 197 字** ——它保留了相当长的原文段落，不是标题党
- **标签仅 3 个**（`#数学` `#Update` `#ChatGPT` 各 1 次）——**几乎完全不打标签**，与 FinanceNewsDaily 的 1,140 个标签形成极端对比

**中位 197 字 + 不打标签 + 保留 via 署名，三者合起来说明：它的处理逻辑是"原样搬"，而不是"重新编辑"。**

## 四、成本

**4.1 一次性启动成本**

| 项 | 估算 | 说明 |

| 多源采集 + 转发管线 | ¥1,000–6,000 | 12 个源，含 TG 频道监听与 RSS/状态页 |
| Telegraph 转存 | ¥0–1,000 | 长文超 4,096 字的处理 |
| **合计** | **¥1,000–7,000** | |

**明显低于 FinanceNewsDaily（¥6,000–28,000）**，因为它省掉了三样最贵的东西：**实体标注、摘要生成、AI 评论。**

**4.2 经常性成本**

| 项 | 估算 | 说明 |
|---|---|---|
| VPS / 常驻进程 | ¥30–150/月 | 持续轮询，负载很轻 |
| LLM API | **¥0–100/月** | **可能完全为零**——正文中位 197 字且保留 via 署名，看不出改写痕迹；部分标题的中文化可能过了一次翻译 |
| 人力 | **1–5 小时/月** | 全自动。人的工作只剩加删源和处理挂掉的抓取 |
| **现金合计** | **¥30–250/月** | |

**它是"高产出 / 低投入"的极端案例**：每天 76 条内容，月现金成本可能不到 ¥250。**代价是内容重复、ERR 垫底、以及把流量送给上游。**

## 五、收益

| 路径 | 样本内证据 | 估算 |
|---|---|---|
| 广告帖 | **0 条。** 关键词命中「广告 49、订阅 36、投放 13、付费 15、aff 6」，逐条核对**全部是 AI 新闻正文用词**（"OpenAI 收紧 ChatGPT 广告政策""Gemini 每日简报向免费订阅用户开放"），无一条是自营招商 | **¥0** |
| 导流 / 联盟 | 300 个 t.me 链接**全部指向上游频道**，无自有落地页、无 aff 参数 | **¥0** |
| **实测合计** | | **¥0/月** |

**样本期内零变现，且它是本轮唯一一个把流量净输出给别人的号。**

**广告承载力**：2.17 万订阅、中位阅读 240、日曝光约 18,000 次、月约 55 万次。**AI/科技类 CPM ¥50–120，折算月度承载力约 ¥2,700–6,600。**

**区间宽的原因**：(1) 无任何报价信息；(2) **75.9 条/天的刷屏会严重压低广告位价值——广告夹在 76 条里，被看到的概率和普通帖一样只有 240 次**，买家会按实际阅读而非订阅数还价；(3) 4 天窗口太短。

**它的经济结构其实相当健康**：月成本 ¥30–250，承载力 ¥2,700–6,600，**毛利空间是本轮里少见的宽。但它一条广告都没接。**

**为什么？两种解释：** 要么它是某人为自己搭的"AI 新闻聚合阅读器"，顺手公开了（这解释了为什么不擦上游页脚——自用时根本不需要擦）；要么它在攒量，还没到变现阶段。**"不擦页脚"这个细节更支持第一种：一个准备卖广告的号，不会每天替竞争对手打 300 次广告。**

## 六、增长

`paid_acquisition: none`。

| 机制 | 证据 | 判读 |
|---|---|---|
| 极高频铺量 | 75.9 条/天 | 覆盖面广，但直接导致 ERR 1.11% |
| 一站聚合 | 12 个上游、24 小时不停 | 对"想一个地方看完所有 AI 新闻"的人有价值 |
| 保留 via 署名 | 每条都标来源 | 转载伦理上做得比多数聚合号好 |
| **流量净输出** | **300 个 t.me 全部指向上游** | **反向增长：它在替上游涨粉** |
| 无买粉特征 | ERR 低但阅读分布仅 1.7 倍、零删除 | 2.17 万订阅是自然积累 |

**它的增长逻辑与本轮其他号相反。** 大多数号想尽办法把流量留在自己这里（互推、footer、bot 深链）；**它每天主动把 300 次点击机会送出去。**

**从数据上看这没有让它吃亏——2.17 万订阅、零删除、稳定的重度用户盘。** 但它也确实没有从中获得任何回报：**转发中位 1、最高 6，说明外部传播几乎不存在。**

**它真正的天花板是 ERR。** 1.11% 意味着 96% 的订阅者已经不看了。**如果去重做对、把每天 76 条压到 20 条，同样的内容能拿到的阅读很可能翻几倍**——这一点在本轮的 awesomeRSSHub 上已经被量化验证过（一次性倒 200 条时单帖 114 阅读，分散发时 2,594）。

## 七、法律风险

> **level: medium。**
>
> **1｜著作权（主要项）。** 它系统性转载 cnBeta、aibase、Bloomberg 及多个 Telegram 频道的新闻正文，正文中位 197 字，保留了较长的原文段落。《著作权法》第十条第（十二）项信息网络传播权——**单纯事实消息不受保护，但 cnBeta 与 aibase 的稿件多为编译改写作品，Bloomberg 稿件更有明确权利归属，转载未获授权。** 责任主体为频道运营者。**减轻情节明显：它每条都标注了 `via 来源`，且保留了上游的原始链接与页脚，主观上不构成冒名，属"标注来源的未授权转载"，与匿名洗稿有量级差别。**
>
> **2｜被转载方的处置权。** 被搬运的 6 个 Telegram 频道可依 Telegram 的版权投诉流程要求下架。**但由于它保留了对方的页脚与导流链接，实际是在为对方引流，被投诉的动机很低**——这一条在现实中大概率不会发生。
>
> **不适用的三条**：不涉及商标侵权（频道名「ChatGPT / AI 新闻聚合」是描述性词组，"ChatGPT" 虽为 OpenAI 商标，但此处属指示性合理使用，用以说明内容主题而非冒充官方，且未使用 OpenAI 的标识或声称关联）；不涉及帮助信息网络犯罪活动罪（0 个收款账号、0 条博彩/色情导流、0 个落地页）；不涉及金融信息服务规定（内容为科技新闻，无投资建议）。
